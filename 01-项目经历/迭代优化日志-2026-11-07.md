# 迭代优化日志 · 2026-11-07（目标停止 23:00）

主线：用户反馈「所有模型都有尖锐棱角，颜色分割线是尖锐曲线而非平滑线段」，
要求分析根因 → 对比结合 L9 画线分割与绑骨拆分 → 找更适合的路 → 多轮迭代 + 每轮反思。

根因推敲见 `L10-棱角根因推敲与路线.md`。以下只记**每轮实测数字与反思**。

---

## R1 修显示链路（22:18）

做了：把 `parts_viewer.html` 那套「抽面 LOD」换成 Blender `DECIMATE` 生成的**闭合曲面 LOD**；
同时把 23 个物体 `parent = Armature`，消除 glTF 导出警告。

| 项 | 结果 |
|---|---|
| 原抽面预览 | 91,610 / 1,745,172 = **5.25%**，抽面必然留孔洞 |
| R1 LOD | 104,688 面 = **6.00%**，DECIMATE collapse 保持闭合曲面，无抽面孔洞 |
| LOD GLB | 1,906,840 B |
| 绑定 | 23/23，各 1 顶点组、1 Armature modifier、parent=PartRig |
| 摆姿势自检 | 旋转 J_00 25° → 顶点世界位移 0.027215（确实跟着动） |

**反思**：抽面（sampling faces）与降面（decimation）不是一回事。前者只保留部分三角形，
留下的洞会把连续曲面显示成碎片；后者重建闭合网格。上一版预览的「颗粒感」有一大半
是我自己用错误的 LOD 方式造出来的，不该让用户背这个锅。

## R2 严格 flat / smooth 对照（22:18）

发现并修了上一版的 bug：首版在 `Weighted Normal` **apply 之后**才把 `use_smooth=False`
渲染 flat 图，此时自定义法线已覆盖开关，对照失真。R2 改为在做任何光滑处理**之前**
渲染 flat，两图共用同一套分色材质 / 相机 / 灯光。

| 版本 | mean abs 像素差 | >2 级差异像素 |
|---|---:|---:|
| 首版（污染） | 0.1297 | 1.76% |
| **R2 严格对照** | **0.0962** | **0.97%** |

**反思（重要，反直觉）**：修好对照后差异**更小**了。说明 `Shade Smooth` 对这个模型
几乎不起作用——因为中位二面角只有 2.32°，绝大多数相邻面本来就近乎共面，
flat 与 smooth 的法线差别肉眼难辨。**我上一轮开的药确实不对症**：
用户说的「看起来挺光滑，实际还有棱角」是几何/边界问题，不是着色问题。
这一轮把「着色平滑能解决棱角」正式撤销。

## R3 逐件几何圆润化：全局 Taubin 参数扫描（22:24）

口径：不改拓扑、不增删面；跨块共享顶点实测 0，故全局 Taubin 等价于逐件独立。
参数 λ=0.5 / μ=−0.53，扫描 iters = 0/1/2/4/8/16/32，每轮测二面角、体积、
顶点位移、23 件最近邻间隙、穿插对数。

| iters | 二面角 p50 | p90 | ≥30° 边 | 体积变化 | 位移中位 / 最大 | 间隙中位 / 最小 | 穿插 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 | 2.32° | 12.51° | 1.912% | — | 0 / 0 | 0.00037 / 0.00012 | 0 |
| 1 | 2.20° | 11.74° | **1.504%** | +0.027% | 0.00006 / 0.00455 | 0.00035 / 0.00011 | 0 |
| 2 | 2.14° | 11.54° | 1.445% | +0.053% | 0.00010 / 0.00719 | 0.00040 / 0.00013 | 0 |
| 4 | 2.10° | 11.43% | 1.418% | +0.101% | 0.00014 / 0.00988 | 0.00040 / 0.00015 | 0 |
| 8 | 2.07° | 11.33° | 1.432% | +0.193% | 0.00018 / 0.01248 | 0.00042 / 0.00014 | 0 |
| 16 | 2.05° | 11.22° | 1.449% | +0.366% | 0.00021 / 0.01445 | 0.00038 / 0.00013 | 0 |
| 32 | 2.03° | 11.13° | 1.481% | +0.689% | 0.00024 / 0.01606 | 0.00028 / 0.00013 | 0 |

拐点：it=1 时 gain/cost 最高（4.519），之后单调劣化；≥30° 占比在 it=4 触底后**回升**。

**反思（撤销该路线为默认）**：
1. 收益极小：≥30° 尖锐边最多只降 0.49 个百分点，且很快饱和反转——
   过度平滑让原本平整的大装甲板起伏，反而制造新的高曲率边。
2. **体积是膨胀不是收缩**（+0.027% → +0.689%），说明 λ/μ 这对参数在低频上净放大，
   与「Taubin 保体积」的预期相反；若用于打印，零件会变大、装配变紧。
3. 最大顶点位移 0.00455 是最小装配间隙 0.00012 的 **38 倍**。采样法没检测到穿插
   不等于没有穿插（采样只取每件 3000 点），这个风险不能用「inter=0」掩盖。
4. 全局平滑一律作用于所有顶点，包括那些本来就该保持锐利的装甲棱线——
   与用户「要平滑连接但保留设计」的诉求相反。

→ **R3 结论：全局 Taubin 不作为默认交付**，`round_parts/` 仅留作对照实验。
下一轮改为**只针对尖锐边**的局部圆角（feature-targeted），平面区不动。

## R4 尖锐边倒圆角 / Bevel 宽度扫描（22:24–22:31）

在 `parts_rigged.blend` 上叠加 `BEVEL`（limit=ANGLE ≥22°、segments=3）+ Weighted Normal，
modifier 不 apply，Blender 里可调；渲染圆润版并保存 `parts_bevel_round.blend`。

| 项 | 结果 |
|---|---|
| modifier 链 | `BEVEL → WEIGHTED_NORMAL → ARMATURE`（23/23 正确） |
| 求值面数 | 1,745,172 → 2,267,516（**+29.93%**） |
| 与光滑版像素差 | mean 0.0713，>2 级差异 **0.95%** |

宽度扫描 0 / 0.0012 / 0.004 / 0.010：

| width | 面数变化 | 与光滑版 mean 差 | >2 级 |
|---:|---:|---:|---:|
| 0 | +0.00% | 0.0220 | 0.08% |
| 0.0012 | +29.93% | 0.0713 | 0.95% |
| 0.0040 | +29.93% | 0.0713 | 0.95% |
| 0.0100 | +29.93% | 0.0713 | 0.95% |

**反思（撤销该路线）**：三个不同 width 的面数与渲染图**逐位相同** → Blender 的
`clamp_overlap` 在 174 万面密集三角网格上把圆角宽度钳死，调参完全无效。
即使生效，视觉收益也只有 0.95% 像素、却要多算 52 万面。
→ **在原始拓扑上做倒圆角不可行**；真要圆角必须先重划分网格，而重划分会
因装配间隙只有 0.00007 量级而必然把 23 件粘死。此路封死，如实记录。

## R5 显示层收口 + 分色边界量化（22:31–22:38）

生成 `gen_viewer_lod.py` → `parts_viewer_lod.html`（5.04 MB 单文件离线）：
数据源换成 Blender DECIMATE 的**闭合曲面 LOD**，法线用 LOD 平滑顶点法线，
抗锯齿 + pixelRatio 2，按 F 可切平面/光滑着色。

无头浏览器自检全绿：
```
parts 23 / faces 104688 / verts 52342
watertight_parts 23/23 / boundary_edges 0 / nonmanifold_edges 0
central_ray_hit true / lod_ratio 0.05999 / flat_shading_default false
```
截图确认：连续分色实体，**无抽面孔洞**（旧版 91,610 面留孔洞 → 颗粒感主因之一）。

分色边界量化（`boundary_metrics.json`）：边界像素 31,889（2.635% 全图）；
137 条可追踪扫描行中 43.80% 有 |Δx|>1 跳变、p90 15.2 px。
放大证据见 `分色边界-放大证据.png`。

**反思**：到这里可以定案了——
1. 颗粒感已修（显示层），且是**我自己造的**，不是模型；
2. 着色平滑、倒圆角、全局平滑三条「自动变圆」的路全部实测为低收益或高代价；
3. 剩下「颜色分割线尖锐」是**硬标签 + 离散三角化**的必然结果，
   要变成平滑线段只能由人指定线在哪，再用 L9 的 `refine_seam.py` 加工；
4. 与「可拆 23 件」存在内在矛盾，必须让用户选风格，不能替他决定。

→ 路线 C（人工定线 + agent 平滑 + 按线切分 + 复用本轮骨架）写入
`L10-棱角根因推敲与路线.md` §6。**本轮到此收口，不擅自改源几何。**

## R6 提高闭合 LOD 密度，缩短「尖锐曲线」的折线段（22:40）

反思 R5 时发现一个自己引入的副作用：**DECIMATE 到 6% 虽无孔洞，但轮廓会被
多边形化得更厉害**——降面越长，沿 silhouette 的折线段越长，恰好加重用户说的
「颜色分割线是尖锐的曲线」。于是生成 20% 闭合 LOD 并做几何量化。

| 指标 | LOD 6% | LOD 20% |
|---|---:|---:|
| 面数 | 104,688 | **349,020** |
| 顶点 | 52,342 | 174,508 |
| 闭合零件 | 23/23 | 23/23 |
| 边界边 / 非流形 | 0 / 0 | 0 / 0 |
| **平均边长** | 0.008073 | **0.004233** |
| HTML 单文件 | 5.04 MB | 13.67 MB |

**平均边长缩短 47.6%**（比值 0.5243）→ 轮廓折线段更短、更接近平滑曲线。
无头浏览器自检：`faces 349020 / watertight 23/23 / boundary 0 / nonmanifold 0 /
central_ray_hit true / lod_ratio 0.19999 / flat_shading_default false`。

**反思**：这是本轮唯一一条「不碰源几何、不违反装配间隙约束、直接改善尖锐轮廓」
的路子，代价只有查看器体积（5.04 → 13.67 MB）。也再次说明：
用户看到的「尖锐」里，有一部分是**显示分辨率**问题，不是模型缺陷。
但必须说清——提高 LOD 只能让折线段变短，**不能把折线变成真正的样条曲线**；
后者仍需路线 C（人工定线 + `refine_seam.py`）。
交付两版：`parts_viewer_lod.html`（轻量）/ `parts_viewer_lod20.html`（轮廓更顺）。

## 目前已固化的判断

- 「所有模型几何上都是棱角」——**证伪**（5 个资产中位二面角 0.15~2.76°）。
- 「Shade Smooth 能解决棱角」——**证伪**（严格对照 0.97% 像素差）。
- 「全局平滑能圆润化」——**不划算，降级为对照实验**。
- 主因收敛到：**显示链路（抽面孔洞 / 点云渲染）+ 沿网格边走的硬分色边界 + 硬表面设计本身**。
- 硬约束不变：装配间隙 0.00007~0.0022，任何跨件几何操作必须先复验穿插。
