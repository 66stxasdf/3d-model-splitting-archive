## 一、用户真正要什么（原话，最重要）

用户 2026-11-10 17:43 原话要点：

> 我想的是可以将**整体的一个公仔建模，分成可以打印的分件**。而不是用 AI 直接一刀切成两半的那种。这种完全没有技术含量。
> 我需要的是 AI 将**人体结构分清楚**：哪里是头、哪里是手、哪里是四肢、哪里是背包、鞋、眼睛、头发之类的这些身体特征。
> 就像昨天那个 Blender 绑骨拆分一样 —— 既然他能将身体的一部分一部分拆出来，拆成一个个**可以有定义的零件**，那么这个光滑的 3D 建模也可以这么拆分出来。
> 最后分出来的零件，经过打印，是**可以通过某些连接结构将它们合在一起**。这个合在一起**一定要符合逻辑**，而不是上面切一刀下面切一刀，两刀直接接在一起。这种没有任何价值。

拆成 7 条需求：

1. 输入：**整体公仔**，一张光滑连续、没有预设缝的一体网格。
2. 系统要**先看懂**语义部位：头 / 手 / 腿 / 背包 / 鞋 / 眼睛 / 头发。
3. 按语义部位切，每件**有名字、有定义**。
4. 每件**单独能打印** —— 必须是封闭实体、有厚度，不能是表面片。
5. 件之间要有**符合逻辑的连接结构**（销/榫/卡扣/磁吸），按受力方向设计。
6. 拼起来要**站稳、不错位、不穿模**。
7. 判定：「上下各切一刀」无技术含量、无价值。

## 二、必须记住的一个事实纠正（容易误解的地方）

**昨天那 23 件不是 AI 识别出来的。** 依据 `13-绑骨拆分-23件刚性蒙皮/README.md`：

- 第 7 行原文：**「这个模型不需要"切"——它本来就是 23 个互相不连通、各自封闭的零件，被打包进了一个 STL。」**
- 连通块 = **23**；跨块共享顶点引用 = **0**；边界边/非流形边 = 0/0。
- 第 41–42 行：**「这不是：…语义骨骼命名（头/左手/躯干）…骨骼名 `J_00 … J_22` 是中性编号，语义名请人工填写。」**

机器只做了两件事：数连通块（`face_adjacency → connected_components`）、用最近距离建最小生成树当骨架。**全程没有一处识别语义**。

所以「既然它能拆，光滑的也能这么拆」这个推论不成立：

- 前者能拆，是因为**源文件本来就有缝**（设计师分件建模的机甲/可动人偶套件）；
- 后者不能这么拆，是因为**它没有缝**。

`13/README.md` 第 112 行自己写了这个矛盾：**「内在矛盾：「平滑连接」与「可拆成 23 件」冲突——连接越平滑，分件缝越不明显。」**

**「光滑」和「好拆」是反的。**

## 三、语义分件其实是四个独立阶段（用户把它们当成了一件）

| 阶段 | 干什么 | 2026 年方案 | 实测 | 我们现状 |
|---|---|---|---|---|
| 语义识别 | 哪块是头手腿 | **PartField**（ICCV 2025，前馈） | mIoU **79.18%**，10 秒/模型 | 无，靠人画线 |
|  |  | SAMPart3D（零样本） | 语义 34.7% / 无类别 53.7%，5~6 分钟/物体 |  |
| 实体化 | 表面片→实心块 | **HoloPart**（ICLR 2026，部件非模态补全） | 补出被遮挡几何 | 部分（布尔切自带封盖） |
| 连接设计 | 销孔/榫卯/磁吸 | ModelSplitter、JointForge、PrusaSlicer | 成熟工程，FDM 间隙 0.2mm | **完全没有** |
| 装配验证 | 拼起来站不站得住 | 物理仿真落下测试 | — | 只量了最近邻间隙 |

### 最关键的一份数据：SNAP3D（CMU，2026-09-11，arXiv）

流程与用户描述完全一致：Hunyuan3D 重建 → **X-Part 语义分件** → 裁掉重叠体积 → 建接触图 → 小件放销/大件开孔 → 物理仿真调销的位置·倾角·半径·插入深度 → 打印 → 手拼。

- 测试集：HY3D-Bench 100 个物体，每个 2~18 件。
- 只用现成语义分件（X-Part / OmniPart / PartCrafter）→ 重力落下测试稳定性 **接近 0%**。
- 加连接 + 仿真优化（SNAP3D）→ **95%** 站住，重叠对降到 0.5%。
- 残余失败几乎全是**接触面太薄、放不下足够大的连接件**。

**结论：光会语义分件，拼起来一定散架。** 用户说的「必须符合逻辑地接回去」不是加分项，是分水岭。

## 四、已有研究结论的正确解读（不要误用）

- **L4** 否掉的是「用几何代价场 `cut_cost` 自己算缝在哪」：对真实接缝 **AUC=0.5185**，无构念效度。
- **L8** 否掉的是「用规则标签自动生成缝冒充真值」：93.6% 可被纯空间分区复述。
- **硬阻塞**：人工设计师接缝真值集仍未产生。

这两条否掉的是**靠几何启发式「算」缝**，没有否掉**从大规模数据「学」语义先验**（PartField 那类）。两者机制不同。
**课题堵住的是「算」，不是「学」。**

## 五、已确定的决策

1. **顺序反过来：先补连接层，再上语义分件。**
   理由：让「两刀切」没价值的，**首先是切完没有连接结构**，其次才是切的位置不够语义。
   - 平面切开 + 好连接 + 对位编号 = 能打印能拼的产品（PrusaSlicer / ModelSplitter / JointForge 都这么做）
   - 语义边界完美 + 没有连接 = 一堆碎块（SNAP3D 实测 0%）
2. **连接层纯代码，不依赖任何模型，立即可做。** 内容：接触面检测 → 接触面积够不够放销 → 按受力方向放销/开孔 → 留 0.2mm 间隙 → 干涉检查 → 两个接触面刻同一编号 → 出装配清单与图示。
3. **语义层要外部模型 + GPU**，需先确认机器有没有 NVIDIA 显卡（用户有 `DGXSpark训练选型论证.md`，可能在考虑）。
4. **不要推翻 `16-分件Agent` 现有架构**：它已经是「确定性骨架 + 硬闸门 + 证据账本」，LLM 只该出现在三个窄位置（任务单解析 / 失败翻译 / 报告叙事），且关掉也能跑。

## 六、三条必须说清的限制

1. **PartField 的 79% 意味着大约 1/5 边界是错的。** 发论文够，直接送打印不够 —— 必须有「人工修边界」或「超阈值拒收」。
2. **语义模型输出是表面片，没有厚度。** 补成打印实体是独立一步（HoloPart 那类），不能省。
3. **眼睛、头发、小配件接触面太小放不下连接件。** 实际做法是嵌槽、磁吸、粘接，不是销（SNAP3D 残余失败即此）。
