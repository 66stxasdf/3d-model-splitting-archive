# 多智能体协同工作台 · 架构设计（v1）

> 目标：把现有「一次只跑一个 ROS 技能 agent」的框架，升级为 **GPT6 式多智能体协同工作台**——
> 多个专职智能体在共享工作台上协作完成复杂任务，并配套可视化控制台。

---

## 1. 现状 → 目标

| | 现状（`agent_main_fixed.py`） | 目标（本工作台） |
|---|---|---|
| 运行单元 | 平台无参启动，一次只跑 `DEFAULT_AGENT` 一个 agent | 一个协调进程内托管多个 agent 协同 |
| 通信 | 无（各 agent 自包含、自旋） | 共享黑板 + 消息总线 |
| 任务 | 单技能一把跑完（`run()`） | 高层目标 → 分解子任务 → 按依赖编排执行 |
| 可观测 | 仅终端日志 | 实时可视化工作台（智能体/任务板/事件流/规划） |

## 2. 分层架构

```
                 ┌──────────────────────────────────────────┐
   高层目标 ───▶ │              Coordinator 协调器            │
                 │  (任务板 / 依赖编排 / 调度 / 失败处理)      │
                 └───────────┬──────────────┬───────────────┘
                 分解任务 ▼             派发/写回 ▼
                 ┌──────────────┐    ┌──────────────────────┐
                 │  Planner     │    │     Blackboard 黑板    │
                 │ (脚本/LLM)   │    │  world / tasks / events│
                 └──────────────┘    └──────────┬───────────┘
                                                │ 共享状态 + 事件
                 ┌──────────────────────────────┼──────────────────────────────┐
                 │  Agent 层（每个技能一个 Agent 实例）                          │
                 │  PerceiveAgent   PickAgent   ScrewAgent   (可无限扩展)       │
                 └──────────────┬───────────────────────────┬─────────────────┘
                       agent↔agent 消息            │
                          ┌───────┴───────┐         ▼
                       Bus 消息总线   Console 可视化工作台 (HTTP + 轮询看板)

```

## 3. 核心模块（`rob/workbench/`）

| 模块 | 职责 |
|---|---|
| `blackboard.py` | 共享状态：`world`（世界状态）、`tasks`（任务板）、`agents`、`events`（事件日志）。线程安全。 |
| `bus.py` | 进程内消息总线：`publish` / `request`（请求-响应）。接口与 ROS2 话题/服务对齐，未来可换分布式实现。 |
| `agent.py` | Agent 协议基类。子类只需实现 `execute(task, ctx)`；通过 `self.progress()` 上报进度，通过 `self.ask()` 跨 agent 请求。 |
| `planner.py` | `ScriptedPlanner`（关键词配方，已内置「装配」配方）+ `LLMPlanner`（可选，提供 `llm_call` 即可启用 GPT 式分解）。 |
| `coordinator.py` | `submit_goal()` 分解任务；`run()` 调度循环：把 `READY` 任务分配给**空闲且能力匹配**的 agent，每任务一线程，完成后解锁下游依赖。 |
| `console.py` | 可视化工作台：本地 HTTP 服务持续写 `state.json`，dashboard 轮询渲染；并支持导出离线 HTML。 |
| `agents/*.py` | 技能智能体：`perceive_worker`（感知）、`pick_worker`（夹取/放置）、`screw_worker`（拧螺丝），当前为**模拟实现**。 |

## 4. Agent 协作契约

每个技能智能体遵循统一契约，从而能被协调器调度、彼此协同：

```python
class Agent:
    def __init__(self, name, capabilities, blackboard, bus): ...
    def can_handle(self, task) -> bool:            # 声明能处理哪类 capability
        ...
    def execute(self, task, ctx) -> dict:          # 处理一个子任务，返回结果
        self.progress(task, "步骤描述")            # 上报进度 → 进事件流/看板
        self.bb.world["key"] = value              # 写回共享世界状态
        self.ask("OtherAgent", "type", {...})     # 跨 agent 请求-响应
```

**协作是如何发生的**：高层目标 → Planner 拆成带依赖的子任务图 → Coordinator 按依赖顺序派发 →
感知 agent 先写 `world["can_pose"]` → 夹取 agent 依赖感知完成 → 放置 → 拧螺丝（依赖放置）。
任一 agent 失败时，下游任务被标记 `blocked`，便于重试/人工介入。

## 5. 如何新增一个技能智能体

1. 在 `workbench/agents/` 下新建 `xxx_worker.py`，继承 `Agent`，`capabilities=["xxx"]`。
2. 实现 `execute(task, ctx)`，用 `self.progress()` 分步上报，结果写入 `self.bb.world`。
3. 在 `main_workbench.py` 的 `agents=[...]` 列表里加入实例即可——无需改协调器。

## 6. 接入真实 ROS（替换模拟）

`mock_robot.simulate()` 的位置即真实接入点。以 `pick_worker` 为例，把模拟步骤替换为对现有
`discovery / servo / kinematics` 的调用（原 `agents/pick_agent/` 已有实现），契约不变：

```python
def execute(self, task, ctx):
    disc = Discovery(self); disc.scan(...); disc.calibrate(...)
    self.progress(task, "已标定关节→电机映射")
    ...  # 与现有 pick_agent 状态机一致，但每步 self.progress 上报
    self.bb.world["can_placed"] = True
```

## 7. 启用 LLM 规划器（GPT 式分解）

```python
from workbench.planner import LLMPlanner
coord = Coordinator(bb, bus, agents, LLMPlanner(llm_call=my_llm_fn))
```
`llm_call(prompt)->str` 返回 JSON 数组（每项含 `name/description/capability/deps`），
解析失败自动回退到 `ScriptedPlanner`。

## 8. 运行

```bash
cd rob/
python main_workbench.py
# 打开控制台: http://127.0.0.1:8765/
# 退出后自动导出离线看板: rob/workbench_console.html
```
