# 可信度分级与已证伪路线

> 这个文件是整套技能里最贵的部分。**项目里已经花掉的实验成本，全在这里。**
> 目的只有一个：让 agent 不再重跑同一条死路。

## 一、四类来源，四种待遇

| `provenance` | 来源 | 可直接放行？ | 必备字段 |
|---|---|---|---|
| `manual` | 人画的线 / 人点的分区 | **是**（唯一可直接放行）| 操作者、时间 |
| `semantic` | 外部分割器（PartField / SAMPart3D / SAMesh）| 否，需人确认边界 | `dataset` `score` |
| `semantic_vlm` | agent 自己看图给的判断 | **否，只能作建议** | 模型名、视角数 |
| `geometric` | 几何量（体积、厚度、平面拟合）| 是（可计算、可复现）| 算法 + 阈值 |

## 二、硬规则：`comparable: false`

```json
"trust": { "dataset": "...", "evidence_kind": "semantic|geometric",
           "score": 0.79, "comparable": false }
```

**`comparable: false` 不是注释，是硬约束。** 语义置信度与几何分数**不可比**，
任何「加权求和 / 归一化后排序 / 综合打分」都等于复活 L4（AUC 0.5185）。

允许的合并方式只有一种：**按来源分档，档内比较，跨档不合并。**
即「三个语义候选内部可以排序；语义候选与几何候选之间只能并列陈述，不能评总分」。

## 三、判断「输入是否同分布」的可操作准则

引用任何 mIoU 之前必须过这一关。四条中任一条不满足 → 该分数**不可引用**，分区视为 `UNKNOWN`：

1. **类别**在模型训练类目内？（人物 / 家具 / 机械 / 交通工具）
2. **风格**一致？（写实扫描 vs 手绘风 vs 卡通 Q 版——Q 版头身比会毁掉先验）
3. **面数密度**同量级？（几千面的低模与十万面的扫描件，面片级标签含义不同）
4. **是否有部件遮挡**？（公仔常见的披风、背包会遮住躯干分界）

四条无法确认时，正确动作是**写 `UNKNOWN` 并说明缺哪条**，不是「大致估一个」。

## 四、已证伪路线（带数据，禁止重跑）

| 编号 | 做了什么 | 结果 | 结论 |
|---|---|---|---|
| **L4** | 几何代价场自动选缝 | **AUC 0.5185**，接缝处代价均值反而**更高** | 无构念效度。自动选缝不可行 |
| **L5** | 换几何特征救 L4 | 5-fold CV 上界 **0.6157**；同层语义接缝 `disc` 仅 **0.043** | 不是特征不好，是这条路本身没有信号 |
| **L7** | 用「闭合环 / 连通分量数」验真 | — | **撤销**。只能查出碎裂，查不出「整条缝平移一格」 |
| **L8** | 用规则标签生成「语义真值」 | **93.6%** 可被纯位置硬分区复述 | 不能当监督集，也不能当验收基准 |
| — | 全局 Taubin / Blender Bevel / SDF 重网格 三条「自动变圆」| 均不划算 | 都不做 |
| — | 「最短 / 绕背」补全模式 | 偏差 **85% / 87%** | 补全策略不可用 |

**AUC 0.5185 的含义要讲清楚**：0.5 是随机。0.5185 等于**抛硬币**。
接缝均值更高意味着这个代价场在接缝处**反而更平滑**——方向完全反了。

## 五、外部分割器的真实水平（2026）

| 模型 | 报告指标 | 换数据集后 |
|---|---|---|
| **PartField** | mIoU **79.18**（10s/模型）| PartNeXt **50.22** / PartNetE **59.10** |
| SAMPart3D | 53.47 | — |
| SAMesh | 56.86 | — |
| Point2Part | 69.80 | — |

**换数据集掉 20 点以上**，而所有对外文案只引 79。
所以：

- **79% ≈ 每 5 条边界里有 1 条是错的。** 边界错在公仔上通常落在脸或手上，是最不能错的地方。
- 该分数**只在训练分布内成立**，引用时必须同时报「数据集 + 是否同分布」。
- 分件任务对边界错误**没有容错**：mIoU 是像素级平均，而分件是「一条缝错 = 一件废」。

## 六、连接 vs 分割：价值分水岭

SNAP3D（CMU）实测：

| 配置 | 重力落下稳定性 |
|---|---|
| 只用语义分件，不设计连接 | **≈ 0%** |
| 加连接结构 + 物理仿真 | **95%** |

**结论：分件做对不等于能装配。** 分割的产出是「几块」，
可交付的产出是「几块能拼回去且不散」。这条决定了 `joint-design` 的优先级高于 `part-semantics`。

## 七、项目内实测（优先级高于外部文献）

| 事实 | 数据 | 用在哪 |
|---|---|---|
| 薄厚不对称 | A 侧 **27.6mm** / B 侧 **4.2mm** | 销必须长在薄件、孔开在厚件 |
| 做反的后果 | 「3mm 的销插 2mm」= 筷子插豆腐 | `joint-design` 立即停手项 |
| 小件接触面 | < **28.3mm²**（≈ 直径 6mm 圆）放不下两根销 | 改磁吸 / 嵌槽 / 粘接 |
| 单位状态 | `unit_confirmed: false`（**至今未实测标定**）| 所有涉及尺寸的结论上限 `PASS_WITH_MANUAL` |

最后一条要特别注意：**单位从未实测标定**。这意味着「27.6mm」这个读数本身的绝对性是有条件的
（依赖源文件声明的单位）。技能里凡引用绝对尺寸，必须同时声明「单位未标定」。

**抽出的经验（本仓通用）**：
1. 结论要带**版本与时间**——0.1.0 的断言在 0.2.0 失效，没时间戳就无法判断该不该重验。
2. **形式变了不等于判断错了**（回退、导出绕过两条换了形式但结论仍成立）；
   反过来，**契约结构变了，旧断言可能整个反号**（语义断链 → 语义直产零件）。两类要分开记。
3. **检查器自身也要有失效模式**：新增检查必须配负向实验（造坏样例确认它立刻 FAIL）。
4. 删掉错误结论 = 同时删掉「当初为什么错」和「下次怎么认出来」。保留它，标上判错依据。
5. **「不是 id 的契约字段」是漂移重灾区** —— 输入门、常量阈值、校验器实现都不在 id 表里，
   存在性检查一个都看不见。凡是机器能读的契约字段，都要有一张**全量对账表**，
   加减一项就 FAIL；否则契约悄悄长大，技能原地不动，表面全绿。
6. **检查器的「合法集合」要随契约一起长大**：`scale_resolved` 这种自造名，
   直到把幻觉前缀改成从契约动态生成才被抓出来。手写前缀表本身就是一个陈旧快照。
