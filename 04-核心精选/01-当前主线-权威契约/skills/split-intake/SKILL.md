# 接单裁定

## 一、立即停手的情形

**按严重性排序。命中任意一条，不许继续跑后面的环节。**

### 1. 单位未确认 → 硬阻断

`scale_resolved` 为空，或 `scale_source` 取的是默认值（`default` / `assumed`）时，**一律停**。

> ⚠️ **口径误用（2026-11-12 标记）**：上面 `scale_resolved` 是本仓自造名，**契约里没有这个字段**。
> `probe_import` 的 `writes` 实际是 `model_path` / `src_sha` / **`scale`** / `scale_source`。
> 判错依据：`manifest.json` 的 `probe_import.writes`；由 `check_terms.py` 第 4 类动态前缀抓出。
> **现结论**：读 `$value.scale`，判空与判默认值的逻辑不变。旧名保留在此供回溯，
> 台账 → `refs/provenance.md` §8。

理由不是谨慎，是这类错误**静默且不可逆**：英寸当毫米是 25.4 倍。
一个 180mm 的手办会变成 7mm，此时体积、壁厚、销径全部错了 16000 倍，
但 STL 没有单位字段，软件打开照样显示「模型」——**没有任何一步会报错**。

自查判据（人物类公仔）：

| 高度 | 判断 |
|---|---|
| 20–400 mm | 正常，继续 |
| 7–20 mm | **疑英寸误当毫米**（原尺寸 180–500mm）|
| < 7 mm 或 > 2000 mm | 比例或单位必有一错 |

超出区间时正确动作：**停下问「这个模型的实际高度是多少厘米」**，不要用包围盒反推。
人给的答案比任何启发式都可靠，且这句话只花一次交互。

### 2. 拓扑不合格 → 停，不要「先切了再说」

- 非水密（`watertight == false`）
- 边界边 > 0（`boundary_edges > 0`）
- 非流形边 > 0
- 绕序不一致

布尔运算在非水密网格上的行为是**未定义**的：它可能成功、可能切出空心壳、
可能产出一个「看起来对但体积不对」的件。最后一种最危险——它能通过几乎所有检查。

### 3. 多连通块且不是套件 → 停，先问清

`components > 1` 有两种完全不同的含义：
- **套件**（本来就是一整套零件）→ 不该走切割，该走装配
- **坏模型**（散落碎片、悬浮小片）→ 不该切，该修复

判据：看各连通块的体积占比。**任一非主块 > 总体积 5%** → 可能真是套件；
全部 < 1% → 是碎片。分不清就问。

### 4. 超出打印平台且用户未同意拆件 → 停

「装不下所以要拆」和「想要分件」是两个需求。前者要问平台尺寸，后者要问缝位。

### 5. 想放宽水密策略 → 必须显式

`policy.allow_nonwatertight_source` 是**开关**，不是默认值。
放宽时必须：得到同意 → 报告里写明「本次在非水密源上运行」→ 后续所有结论降级为 `PASS_WITH_WARN`。

自行假定「反正能放宽」等于把 G0 这条门拆掉。

## 二、判据（对应 G0，细节见 `refs/gates.md`）

全部满足才放行：

| 判定项 | 条件 | 可否放宽 |
|---|---|---|
| 文件可读 | `probe.ok` | 否 |
| 面数 > 0 | `faces > 0` | 否 |
| sha256 已落账 | 非空 | 否 |
| 水密 | `watertight` | 是（非默认）|
| 单一连通块 | `components == 1` | 是（非默认）|
| 边界边为 0 | `boundary_edges == 0` | 是（非默认）|

三态铁律：**缺字段是 `UNKNOWN`，不是 `PASS`**。
`boundary_edges` 缺失时不能用 `.get(k, 0)` 兜底成 0——那是把「没查」记成「查了没事」。

### 2.2 局部厚度（G0 之外，但必须查）

入厂就要查厚度。理由不是 G0 要求，而是**它决定后面所有绝对尺寸是否有意义**：
不知道哪侧厚，`joint-design` 就只能靠包围盒猜——那正是「销做在厚件上」的来源。

判据看**分位数与薄区占比**，不看单点最小值：

| 指标 | 阈值 | 含义 |
|---|---|---|
| p05 厚度 | ≥ **1.2 mm** | 95% 的表面够厚 |
| 薄区面积占比（< 0.8mm）| ≤ **2%** | 少量尖角可接受 |
| 单点最小厚度 | 只记录 | **不作为判据** |

**为什么不用最小值**：任何手办的发梢、指尖、衣角都是零点几毫米的薄片，
切片时会被当作轮廓的一部分处理，不影响可打印性。用最小值判，
会把每一个正常模型都判成「不可打印」——这个错误方向最糟，因为它让整条链永远无法开始。

实测参照（`astronaut_kid_pipeline.stl`，200000 面）：

```
min 0.255 / p05 2.02 / median 13.76 / p95 39.02  → 整体合格，0.255 是局部尖角
```

若 p05 掉到 1.0 以下，才是大面积偏薄，此时该退回让用户加厚或换打印方向。

计算方法：从每个面中心沿法向反向打射线，取首个命中距离（约 20 行，`_tryout/probe.py` 有可跑实现）。
不必全表面算，随机采样 3000 个面就够——分位数不需要全量。

## 三、需要的证据

`intake.json` 必须含：

- `source.sha256` — 指纹。后续所有「切的是同一份几何」都靠它
- `welded.faces` / `components` / `boundary_edges` / `watertight`
- `scale_resolved` / `scale_source` — **单位从哪读出来的**
  ⚠️ **口径误用**：`scale_resolved` 应为 `$value.scale`（契约真实字段名，见第 1 条标记）；此处保留原名留痕
- `soup` — 未焊接前的面片统计（判断是否「像是被炸开的」）
- **局部厚度分布**（p05 / 薄区占比 / 能逐点查询的厚度场）— 不是 G0 要求，
  但 `joint-design` 判「销长在哪侧」必须有它

最后一条容易漏。厚度不是入厂检查项，却是**连接设计的唯一输入**。
没有它，下游只能靠包围盒猜哪边厚——那正是「销做在厚件上」这个错误的来源。

注意：要的不是一个全局最小值，是**能在接触面上逐点查询**的厚度。
只给一个数，`joint-design` 依然判不了哪侧厚。

## 四、放行条件

`input_ok` 校验器通过，且 `intake.json` 已落盘。

放行时必须在报告里写清两件事：
1. 单位依据是什么（`scale_source`）
2. 是否用了放宽策略（用了则后续结论上限 `PASS_WITH_WARN`）

## 五、能力状态

| 能力 | 状态 | 说明 |
|---|---|---|
| 水密 / 连通 / 边界边 / 绕序 | `implemented` | 契约已定，实现由 `probe_import` 提供 |
| 单位识别 | `advisory` | 只能读文件声明与启发式，**不能验证物理尺寸** |
| 打印平台尺寸校验 | `absent` | 平台尺寸在用户手里，必须索取，不得猜 |
| 网格修复 | `absent` | 本链不修模型。不合格就退回，不要让 agent 自己补洞 |

`absent` 项一律：出 `UNKNOWN` + 写一条人工动作项，**不得用截图或估计糊过去**。
