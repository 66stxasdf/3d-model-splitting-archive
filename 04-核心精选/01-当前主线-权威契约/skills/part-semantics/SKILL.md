# 语义部位分件与标签准入

## 零、能力声明（本技能最重要的一节）

**本技能不具备语义识别能力。** 「这是头、那是手」这种判断，技能写不出来，
提示词也写不出来。技能能做的只有一件事：**裁定已有的分区能不能采信。**

合法输入只有三种，其余一律无效：

| 来源 | 谁能给 | 可信度待遇 |
|---|---|---|
| `manual` | 人指出的部位 | **唯一可直接采信** |
| `semantic` | 外部分割器（PartField / SAMPart3D / SAMesh）| 需人确认边界 |
| `semantic_vlm` | agent 自己看图给的判断 | **只能作建议**，不得作为结论 |

三种都没有（没 GPU、没视觉、没人配合）时，正确输出是**「这一步做不了」**，
不是「我试着分一下」。内核对这个工具的判定正好是：
「这是整条链最关键的一步，也是目前唯一没有现成实现的一步。」

## 一、立即停手的情形

### 1. 认为「校验器全过」就等于「部位认对了」→ 停

0.2.0 起，`segment_semantic` 直接产出 `parts_available`（零件），
后面接 `clean_part` → `verify_part`，看起来链条完整。

但 `verify_part` 只查**水密、自交、体积、壁厚**——这些都是几何性质。
它查不出一块从膝盖上切下来的块「本来该是腿」。

**校验器能证明它是零件，不能证明它是那个部位。** 这是本技能存在的全部理由。

### 2. 想用包围盒 / 位置规则冒充语义分区 → 停

这是最容易被当成「已经解决了」的错误，因为它**便宜、看起来合理、且已被证伪**。

L8 实验：用规则标签生成「语义真值」，结果 **93.6%** 可以被纯位置硬分区复述。
也就是说这个「真值」几乎不含语义信息，它只是坐标的另一种写法。

典型伪装：「上半部分是头、中间是躯干、下半部分是腿」。
对标准站姿人体这句永远成立——正因如此它没有判断力，
遇到蹲姿、举臂、背包就全错，而错误方式是静默的（依然切出三块）。

### 3. 引用 mIoU 前没判「输入是否同分布」→ 停

PartField 报 **79.18**，那是训练分布内。换数据集：

| 数据集 | mIoU |
|---|---|
| 训练分布内 | **79.18** |
| PartNeXt | **50.22** |
| PartNetE | **59.10** |

掉 20 点以上，而所有对外文案只引 79。

**四问必过**（任一不满足 → 分数不可引用，分区记 `UNKNOWN`）：

1. 类别在训练类目内？（人物 / 家具 / 机械 / 交通）
2. 风格一致？（写实扫描 vs 手绘 vs Q 版——Q 版头身比会毁掉先验）
3. 面数密度同量级？（几千面低模与十万面扫描件，面片标签含义不同）
4. 有无部件遮挡？（披风、背包会遮住躯干分界）

### 4. 把语义件退回去当几何块用 → 停

两条路都产出 `parts_available`，但命名规则不同：

| 谁产出 | priority | 件叫什么 |
|---|---|---|
| `segment_semantic` | 10 | 语义名（head / arm / backpack）|
| `cut_plane` | 20 | 位置名（piece_A / piece_B）|

语义件被下游当几何块处理时，`find_contacts` 的 pair 命名（`部件A__部件B`）会错乱，
连接结构挂到错误的部件对上。**命名是契约的一部分，不是装饰。**

反过来也一样：`cut_plane` 切出来的位置名件，不许改叫 head。

### 5. 把语义置信度与几何分数加权 → 停

`trust.comparable: false` 是硬约束。语义分数来自数据集统计，
几何分数来自可复现计算，两者量纲与含义都不同。
加权求和 / 归一化后排序 / 综合打分——**任何形式都等于复活 L4**（AUC 0.5185）。

允许的合并方式只有一种：**分档并列，档内比较，跨档不评总分。**

### 6. 把「79% 准确」理解成「基本可用」→ 停

79% 是**面片级平均**。分件是「一条边界错 = 一件废」的任务。
换算过来：**每 5 条边界里约 1 条是错的**，而错的位置通常在脸和手。

两者对错误的容忍度差一个量级。这个换算必须写进报告，不能只写 79。

---

### 7. 没声明 `inputs.model_kind` 就要跑 `segment_semantic` → 停

11-11 内核给这个工具加了**类型声明输入门**（`needs_fields: [inputs.model_kind]`）。
契约没有顶层 `inputs` 段，靠 `needs_fields` 控适用条件——否则无真值时会误触发。

规则（内核 T27 已锁）：

- **人声明优先**；模型提议的 `model_kind` 必须经人确认；
- 不确定 → **拒收**，并把分类依据写进 `run.json`；
- 缺这个字段，`segment_semantic` 根本不该被排进计划。

> 别把它当成「再补一个参数」。它是一道岔路闸门：没宣告输入类型就跑语义分件，
> 等于让一个未声明分布的模型去判定，正好撞上第 3 条「输入是否同分布」——
> 那时连该查哪四条都不知道。字段全量对照 → `refs/pack-contract.md` §四之二。

## 二、判据

### 2.1 分区输出

```json
{ "region_id": "R1",
  "label": "head",
  "face_ids": [ ... ],
  "confidence": 0.79,
  "boundary": { "curve_ids": [...], "is_closed": true },
  "provenance": "manual | semantic | semantic_vlm",
  "trust": { "dataset": "PartNet", "evidence_kind": "semantic",
             "score": 0.79, "comparable": false } }
```

四条硬要求：

1. `provenance` 必填，缺了就无法定待遇
2. `boundary.is_closed` 必填——边界不闭合就无法封成实体
3. `trust.comparable` 恒为 `false`
4. `face_ids` 必须是**面片级**索引，不是顶点、不是包围盒

### 2.2 三条现实路径（按机器条件选）

| 路径 | 条件 | 代价 | 主要风险 |
|---|---|---|---|
| A. 前馈模型 | 有 GPU | ~10s/模型 | 分布外掉点；需人确认边界 |
| B. 人工关键点 + 测地距离 | 无 GPU | 每模型几分钟 | 关键点选错导致边界整体偏移 |
| C. 完全人工分区 | 上述都不可用 | 人时 | 唯一可靠，也最贵 |

**B 的做法**：人工点 6–8 个关键点（头顶点、颈部、肩、腕、踝……），
用测地距离 + 曲率分水岭推边界。慢但可控，失败时人能看懂错在哪——
这是它相对 A 的唯一优势，也是没 GPU 时不该直接放弃语义的理由。

### 2.3 采信判据

| 来源 | 可否采信 | 附加条件 |
|---|---|---|
| `manual` | 可 | 记录操作者与时间 |
| `semantic` | 需人确认边界 | 报 dataset + 同分布四问结论 |
| `semantic_vlm` | **不可** | 只能作为画线参考 |

## 三、需要的证据

`segment_semantic` 的 `values` 必须含：

- `part_ids` — 部位清单（写进契约的 `writes`）
- `parts_dir` — 每件网格的落盘目录
- 每个分区的 `provenance` 与 `trust`
- `evidence` — 用了哪个模型 / 哪组人工关键点

失败码：`SEGMENTATION_EMPTY`（分区为空）/ `LABELS_INCONSISTENT`（标签与面片对不上）。

**`SEGMENTATION_EMPTY` ≠「这个模型没有部位」。** 它等于「我没分出来」。
两者在报告里必须区分，否则会得出「该模型不可分件」的错误结论。

### 上游不必自查（契约已保证）

`segment_semantic` 的 `requires` 是 `[input_ok, lod_ready]`，而它读的 `$value.lod_path`
由 `prep_lod` 声明在 `writes` 里。**doctor 会静态核对「谁写 → 谁读 → 谁 requires」这条链，
不成立就判死**，所以「上游是否就绪」不是技能该管的事。

别把这条写成技能纪律。「确认 `lod_ready` 已成立」是**能被静态判定**的，
按本仓的判据归内核；写成提示词自觉，等于把一件可判定的事交给不可靠的执行者。

技能只保留**错误码的语义归属**——这部分没人能静态判定：

| 码 | 不要读成 |
|---|---|
| `MISSING_PARAM` | **不是**「分割器没装好」「环境有问题」。它是参数取不到，先查上游事实或任务单字段 |

（历史：0.2.0 早期 `requires` 漏了 `lod_ready`，孤跑会抛 `MISSING_PARAM` 并被误诊为环境问题；
内核已于 21:35 补齐契约，并加静态检查 T25 锁住这一类隐式依赖。）

## 四、放行条件

`parts_available` 成立（由本技能的 `segment_semantic` 产出），且：

1. 每个分区都有 `provenance` 与 `trust`
2. 非 `manual` 来源的分区，边界已由人确认
3. 报告里写明「部位划分的正确性未经几何校验器验证，仅经人确认」
4. 件名是语义名，未与位置名混用
5. `inputs.model_kind` 已由人声明或确认，分类依据进了 `run.json`

### 4.1 有 `ref_parts` 时，放行线由评估器给，不由感觉给

11-11 内核把 `parts_available` 校验器**填成了真实现**（此前是桩）：

| 条件 | 判定 |
|---|---|
| 有 `ref_parts` | 表面采样 IoU + 漏分 / 多分件数；逐件 IoU 下限 `const.semantic_min_iou = 0.6` |
| 语义匹配下限 | `const.semantic_match_floor = 0.5` |
| **无 `ref_parts`** | **`UNKNOWN` 并拒收** —— 不是 PASS，也不是「大致看一下」|

这两个数是**回归尺子上的阈值**，不是「语义正确率」。
它们量的是「与这套人工标注的一致度」，不能拿去证明「头认对了」（见停手第 1 条）。
48 件参数化真值集被裁决降级为回归尺子、不作训练样本（`refs/provenance.md` §4），
正是这个口径。

`parts_available` 不成立时不算最终失败：还有人工割线这条路
（`seam_ingest` → `route_branch` → `cut_plane`）。正确动作是**转人工割线**，
不是硬用规则标签凑一份。

## 五、能力状态

| 能力 | 状态 | 说明 |
|---|---|---|
| 外部分割器调用 | `absent` | 契约已登记，实现为空（桩）|
| 人工关键点 + 测地分水岭 | `absent` | 同上 |
| 表面片 → 实体 | `absent` | HoloPart 类问题，无对应事实 |
| 分布外检测 | `absent` | 只能靠人回答四问 |
| **部位正确性校验** | `absent` | **校验器查不了这个**（见停手第 1 条）|
| 标签可信度裁定 | **本技能的唯一职责** | 不依赖任何工具，纯判断 |

最后两行是同一件事的两面：**校验链能管「是不是零件」，管不了「是不是那个部位」**。
这个缺口不会因为工具补齐而消失，只能靠人确认。
