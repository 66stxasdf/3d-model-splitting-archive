# 割线准入与缝位

## 零、必须先分清的两件事

| 问题 | 谁回答 | 工具能不能算 |
|---|---|---|
| 这条线**几何上合法**吗？ | `seam_ingest` | **能**（闭合 / 回折 / 拟合残差）|
| 这条线**该不该在这里**？ | **人** | **不能** |

**准入通过 ≠ 缝位正确。** 一条完全闭合、无回折、拟合完美的缝，
可以正好从眼睛中间穿过去——G3 会给它 PASS。这就是本技能存在的原因：
把「能切」和「该切」分开，不让前者的通过冒充后者的结论。

**本技能是可选支路。** 契约里 `seam_ok` 与 `route_known` 同属 `optional` 组：
没人画割线时，这条支路**根本不参与**，整件走 `segment_semantic`。

所以「没有割线」不是失败，是另一条路；而「有割线」就该走到底，不要中途转去语义。
两条路混着走会毁掉零件命名（见停手第 4 条）。

---

> **契约输入门（11-11 新增）**：`seam_ingest` 的 `needs_fields` 是 `inputs.seam`。
> 这不是「参数可选」，是**适用条件**：任务单里没有 `seam` 字段，该工具根本不该被排进计划，
> 规划器应转 `segment_semantic`（priority 10）。上面「本技能是可选支路」说的就是它的契约依据。
> 字段与 `needs_fields` 全量对照 → `refs/pack-contract.md` §四之二。

## 一、立即停手的情形

### 1. 想用几何代价场自动选缝 → 停

已实测证伪：**AUC 0.5185**。0.5 是随机，0.5185 等于抛硬币。
更糟的是接缝处的代价均值**反而更高**——方向完全反了。

换特征是救不回来的：5-fold CV 上界 **0.6157**，同层语义接缝的可分性 `disc` 仅 **0.043**。
这条路没有信号，不是调参能解决的。

### 2. 想用「闭合环 / 连通分量数」证明缝有效 → 停

L7 已撤销这条做法。它只能查出「碎裂」，查不出「整条缝平移一格」：
一条闭合并把模型切成两块的缝，平移 5mm 之后**依然闭合、依然切成两块**。
判定量对位移不敏感，就不是有效验真。

### 3. 缝落在禁切区 → 停

- 面部（五官所在区域）
- 眼睛、嘴（小件，切了就散）
- 高曲率高光区（切面会在视觉最显眼处）
- 薄壁区（厚度 < 1.2mm，切完一侧直接没料）
- 已有细特征处（发丝、手指、飘带边）

**检测能力现状：`absent`。** 没有面部分类器，没有曲率阈值化工具。
所以这一条靠**人确认**，不能声称「已自动避开」。

### 4. 想混用两条分件路径 → 停

0.2.0 契约里有两条**互斥**的路，都产出 `parts_available`：

| 路径 | 工具 | 产出的是什么 |
|---|---|---|
| 语义分件 | `segment_semantic`（priority **10**）| 有名字的部位：head / arm / backpack |
| 人工割线 | `seam_ingest` → `route_branch` → `cut_plane`（priority **20**）| 几何块：piece_A / piece_B |

`cut_plane` 的契约里写死了一句：**它切出来的是几何块，不是语义部位，命名只能按位置，
不能编成 head / arm。** 这是为了防止「切了两块就管它们叫头和身子」。

所以不许先语义分一遍、再对其中某件补一刀、然后把结果混在一起当零件集：
零件 ID 空间会混进两种命名法，下游 `find_contacts` 的 pair 命名（`部件A__部件B`）直接错乱。

**选一条走到底。** 要语义就整件走语义；要精确控制就整件画线。
人明确画了割线时按人的切（priority 20 > 10），不要用算法去改人的决定。

### 5. 缝穿过非流形边或已存在的边界边 → 停

那会在切割时产生不可预测的连通性，产出的件数可能不是 2。

## 二、判据

### 2.1 准入（`seam_ingest` → `seam_ok`，对应 G3）

| 判定项 | 条件 |
|---|---|
| 解析到点 | `n_points > 0`（支持四级回退解析）|
| 闭合 | `declared_closed == true`，且首尾实际间隙在容差内 |
| 无回折 | 相邻段折叠角 **< 150°**（即不出现锐角折返）|
| 点数 | ≥ 12（低于此无法表达一条有形状的缝）|
| 无自交 | 投影到拟合平面后不自交 |

**特殊：`undecidable` 为真且未全过 → `UNKNOWN`，不是 `FAIL`。**
「判不了」和「不合格」必须分开记：前者要补证据，后者要重画。

### 2.2 路由（`route_branch` → `route_known`，对应 G4）

| 平面拟合残差 | 分支 | 含义 |
|---|---|---|
| ≤ **0.5 mm**（`coplanar_rms_mm`）| `plane` | 半空间盒布尔，最快最稳 |
| > 0.5 mm | `curved` | 扫掠切，慢 40% 且**必留薄片** |

**阈值不要自己调。** 0.5mm 是「缝是否近似平面」的判据，
调大就会把明显弯曲的缝塞进平面分支，结果是一侧被切掉太多或太少，
而 G5 只检查「两件存在、新鲜、非空」——它会通过。

任务单若用 `constraints.branch` 强制分支，必须服从，并在报告里记「分支是被强制的」。

### 2.3 缝位优先级（人画线时的建议顺序）

| 优先 | 位置 | 理由 |
|---|---|---|
| 1 | 衣物分界（领口、腰线、袖口）| 视觉上是「本来就该分开」的地方 |
| 2 | 发丝之间、发与额的分界 | 天然沟槽，切面易隐藏 |
| 3 | 结构关节（肩、髋、颈）| 有解剖依据，装配后能对位 |
| 4 | 面板边、装甲缝 | 硬表面模型的天然分界 |
| 5 | 背面 / 底面隐藏线 | 实在无处可切时的兜底 |

**切面宜取平面且朝床。** 平切面同时拿到两件好处：切割稳定（走 `plane` 分支）、
打印时切面贴床（免支撑、附着好）。这一条经常能同时优化切割和打印两件事。

## 三、需要的证据

- 割线文件本身（点序列或曲线 id），以及它是**谁给的**（`provenance`）
- `declared_closed`、`n_points`、`topology`、`refit_plane`、`rms`
- 若是 `curved` 分支：拟合残差的具体值与分布（不是只看均值）
- 人确认记录：谁在什么时候确认了「这条缝位置可以」

最后一条在报告里经常缺失。没有它，后续无法区分「缝是机器选的」还是「人确认过的」——
而这两者的可信度差距，正是 `refs/provenance.md` 整个文件在讲的事。

---

## 四、放行条件

`seam_ok` 与 `route_known` 同时成立，且：

1. 缝位有明确来源：`manual` 可直接放行；`semantic` 需人确认边界；`geometric` **不得单独放行**
2. 禁切区已人明确认（因为检测能力 `absent`）
3. 若 `route_known` 判成 `curved` → **停下来**。契约里 `route_branch` 说「曲缝走贴合切割」，
   但 0.2.0 只登记了 `cut_plane` 一个切割工具（半空间布尔），**曲面分支没有对应工具**。
   这是契约缺口，不是你能绕过的事——见「五、能力状态」。

## 五、能力状态

| 能力 | 状态 | 说明 |
|---|---|---|
| 闭合 / 回折 / 自交 / 点数 | `implemented` | `seam_ingest` |
| 平面拟合与路由 | `implemented` | `route_branch`，阈值 0.5mm |
| **缝位选择** | `absent` | **必须人画**。这是本链最硬的人工依赖 |
| **曲面分支切割** | `absent` | `route_branch` 能判出 `curved`，但 0.2.0 没有对应切割工具 |
| 禁切区识别（面部 / 薄壁 / 高曲率）| `absent` | 无分类器、无曲率工具 |
| 缝位好坏评分 | `absent` | 曾被尝试（L4/L5），已证伪，不再做 |

`absent` 三项合起来意味着：**本技能能拦住坏缝，不能选出好缝。**
报告里必须如实这样写，不能说「缝位已优化」。
