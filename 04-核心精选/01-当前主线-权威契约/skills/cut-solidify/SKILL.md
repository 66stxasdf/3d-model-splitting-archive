# 切割与实体化

这一环有三个真陷阱，每个都会产出「看起来成功」的废件。

## 一、立即停手的情形

### 1. 不降面直接布尔 → 停

原始模型动辄二十万面（实测 `astronaut_kid_pipeline.stl` 就是 200000 面）。
布尔在这个量级上会出现三类静默失败：内部漏面、法向翻转、局部壳体丢失。
三者都能通过「件存在、非空」的检查，只在体积上露馅。

**必须走 `prep_lod`**，降到 `lod_faces = 89954`，且 LOD 体积漂移 **< 1%**。

### 2. 把 `curved` 分支的缝喂给 `cut_plane` → 停

`route_branch` 说得很清楚：平整走半空间布尔，**弯曲走贴合切割**。
但 0.2.0 只登记了 `cut_plane` 一个切割工具，它的契约是「用割线构造**半空间盒**做布尔切分」。

半空间盒是平面。把一条曲缝喂进去，它不会报错——它会用某个拟合平面切下去，
得到两块形状正常、体积也大致守恒的件，**只是缝的位置和你要的不一样**。

所以：`branch == 'curved'` 时必须停。契约里的曲面分支没有对应工具，这是缺口，不是你能绕过的事。

### 3. 把切出来的块命名成 head / arm → 停

`cut_plane` 的契约里写死：「切出来的件是**几何块**不是**语义部位**，命名只能按位置
（`piece_A` / `piece_B`），不能编成 head / arm」。

这条不是洁癖。下游 `find_contacts` 的 pair 命名是 `部件A__部件B`，
一旦 ID 空间里混进两种命名法，接触面对就配不上，连接结构会挂到错误的部件对上。

要语义部位，走 `segment_semantic`；要精确切，就用位置名。两条路别混。

### 4. 拿切割时的内存结果去做复验 → 停

复验的整个意义是「不信工具的自我报告」。若复验读的是工具返回的数组，
它验证的是工具的信念，不是磁盘上的产物。

`verify_part` 必须从 `clean_dir` 的落盘路径重读。

### 5. 单件清理失败就把整批判死 → 停（`skip_instance` 的含义）

`clean_part` / `verify_part` 的失败策略是 **`skip_instance`**：
一件出问题只放弃这一件，其余继续。

所以内核交回的常是「N 件里 M 件通过」。正确处理：

- 失败的件 → 剔除出交付清单，**逐件**写进报告
- 不许把失败件悄悄算进「全部通过」
- 也不许因为一件失败就判整批 `FAILED`

但不许做的是：**把失败件修补后混回去**。清理失败的件通常是不封闭或有碎片，
补一补看起来能过，实际内部结构已经不可信。

## 二、判据

| 环节 | 判定项 | 条件 |
|---|---|---|
| `prep_lod` | LOD 非空 / 单连通 / **体积漂移 <1%** / 数组哈希已记 | 对应 G1 |
| `cut_plane` | 退出码 0 / 报告 ok / 件数 = `part_ids` 长度 / **mtime ≥ run 起点** / 每件字节 > 84 | 对应 G5 |
| `clean_part` | 执行成功 / 各件**未被删主块** / **移除体积 < 1%** | 对应 G6 |

**「mtime ≥ run 起点」防的是读到上一次运行的残留产物。**
这是最容易造假成功的地方：路径对、文件在、字节数正常，只是那是上次的。

**「未被删主块」与「移除体积 < 1%」是一对反向约束**：
前者防把主块当碎片删了，后者防几乎没清干净。两条都得看。

注意 `parts_available` 有**两个产出者**：`segment_semantic`（priority 10）
和 `cut_plane`（priority 20）。本技能只负责后者。看到 `parts_available` 成立时，
先确认它是哪条路产出的——命名规则不同，下游接触面对会因此对不上。

## 三、需要的证据

- `lod.json`：`faces`、`components`、`volume_ratio`、`arrays_sha256`
- 切割报告：`returncode`、`part_ids`、每件 `faces` / `bytes` / 路径 / mtime
- 清理报告：每件清理前后面数、`removed_volume`、总体积
- 每件的命名（位置名还是语义名）及其来源

---

## 四、放行条件

`parts_available` 与 `part_clean` 同时成立，且**至少一件**通过清理。

逐件写清：哪几件成功、哪几件被 `skip_instance` 放弃、放弃原因。

**这里不做最终判定。** 切割通过只意味着「切出来了」，
「切得对不对」由 `verify_part` 判，别在这一环写「切割成功，质量合格」。

## 五、能力状态

| 能力 | 状态 |
|---|---|
| 降面 + LOD 校验 | `implemented` |
| 平面半空间切 | `implemented` |
| **曲面贴合切** | `absent`（`route_branch` 能判出，但没有工具）|
| 单件薄碎片剔除 | `implemented`（`skip_instance`）|
| 表面片补成实体（HoloPart 类问题）| `absent`（契约里没有对应事实）|

`curved` 分支是这条链上最明显的缺口：**能判出来，切不了。**
遇到它只能如实报「分支已判定为曲面，但无对应工具」，不能退化成平面切蒙过去。
