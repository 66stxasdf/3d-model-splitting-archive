用户观察：

## 1. 五层归因（逐层给证据，不臆测）

### L0 数据层：STL 格式只存面法线 —— 成立，但不是主因

抽样源文件 20 万个三角形，存储法线与叉积面法线点积 **100% = 1.000000**。
STL 没有顶点法线、没有平滑组、没有材质、没有骨架。任何导入器（含 Blender）默认
Flat Shading，174 万个 facet 直接可见 → 颗粒感。
→ 这是「导入即棱角」的机制，但**只影响着色，不影响轮廓**。

### L1 几何层：**反证** —— 源模型并不是棱角模型

对 5 个真实资产统一测「内部边二面角」（`np.cross` 面法线 → `arccos` → 取锐角侧）：

| 模型 | 三角面 | 中位 | p90 | p99 | ≥30° | 均值 |
|---|---:|---:|---:|---:|---:|---:|
| 11-07 已拆 23 件 | 1,745,172 | 2.32° | 12.51° | 38.57° | **1.91%** | 5.00° |
| 10-26 A 整体 | 1,499,959 | 2.32° | 15.01° | 51.16° | 3.61% | 5.87° |
| 10-26 B 整体 | 1,499,276 | 0.16° | 2.88° | 32.53° | 1.19% | 1.76° |
| 02 宇航员 GLB | 499,990 | 2.76° | 14.11° | 39.69° | 2.30% | 5.60° |
| 03 Minecraft GLB | 499,980 | 0.15° | 2.45° | 22.25° | 0.30% | 1.43° |

共面片（相邻面夹角 <2° 连成片）：707,076 片，中位 1 面，**67.36% 是单片**；
≥1000 面的大片只有 110 个、覆盖 19.20% 面。

解读：绝大多数相邻面夹角只有几度，是**连续曲面的高精度三角化**；
≥30° 的真尖锐边只占 0.3%~3.6%。所以「所有模型都充满棱角」在几何层面**不成立**。
用户看到的棱角，主要来自下面两层。

### L2 预览层：我自己的产物把连续曲面显示成了碎片 —— **主因**

| 产物 | 实际内容 | 后果 |
|---|---|---|
| `parts_viewer.html` / `parts_preview.glb` | 每零件连续窗口抽面，合计 **91,610 / 1,745,172 = 5.25%** | 抽面必然留孔洞；三角面互不相邻处看起来是碎颗粒 |
| `parts_render_3views.png` | **点云 z-buffer**，每个三角形重心只投 1 个点 + 3×3 膨胀 | 无三角形光栅化、无 AO、无抗锯齿；薄翼出斑点 |
| `parts_rigged.glb` | 1 个 mesh 挤 23 件 + 无差别全顶点平均法线 | 硬边被抹圆，观感「糊」；也不是 Blender 里 23 物体的样子 |

**这一层是我引入的，与源模型无关**，且恰好解释了「看起来挺光滑（大面），实际很多棱角（细部碎）」。

### L3 边界层：颜色分割线为什么是「尖锐曲线」而非「平滑线段」 —— **主因**

分色是按**连通块 rank 对面硬赋值**。两个颜色的交界线只能沿三角网格边走，
因此是**折线**（每段方向由三角形边决定），不是拟合出来的平滑曲线。
折线的转折角直接等于网格局部三角化角度（本模型 p50 2.32°、p99 38.57°），
在轮廓/silhouette 处被放大成可见锯齿。加上无过渡的硬边与像素级阶梯，
就是用户说的「尖锐的曲线」。

> 这与 L9 `seam_draw.html` 里黄色割线的锯齿是**同一个机制**：
> 沿面带走 → 折线 → 视觉锯齿。L9 已用 `refine_seam.py` 解决过一次，可直接迁移。

### L4 设计层：硬表面机甲的尖刺与装甲棱线 —— 是设计，不是 bug

110 个 ≥1000 面的大共面片（平板装甲）、约 5 万条 ≥30° 边（棱线/尖刺）。
「网上那种圆润、平滑连接、方便 3D 打印」是**另一种造型风格**（Q 版 / 有机曲面）。
把它变成那样属于**风格再设计**，不是修 bug，且会损失原设计特征。
另外提醒一个常识性问题：硬表面机甲的锐边在 FDM/光固化上并非不能打印；
真正卡打印的是**极薄尖刺、悬空、0.00007~0.0022 的装配间隙、未封盖的开放面**。

## 2. 约束（决定哪些方案不能用）

1. **装配间隙极小**：23 件最近邻间隙中位 0.00021、最大 0.00221（源 STL 原始单位，单位未知）。
   任何**全局**平滑/膨胀只要位移 > ~1e-4 就会让相邻件互相穿插、23 块重新粘成一个连通块。
   → 必须**逐零件独立处理**，且每轮复验连通块数、间隙、非流形、水密。
2. **平滑会收缩体积**：普通 Laplacian 会整体塌缩并糊掉细节；Taubin（λ/μ 交替）可抑制收缩。
3. **「平滑连接」与「可拆成 23 件」内在矛盾**：连接越平滑，分件缝越不明显；
   若目标是「零件表面圆润 + 分件线清晰平滑」，必须分开处理两件事。
4. **闭环/水密成立 ≠ 切对位置**（L9 已实测：三种补全都水密分 2 块，最短模式小件只有真值 15%）。
   任何平滑后必须复验，不能只看「看起来顺了」。
5. 单位未知，不猜 mm/m；所有长度都是源坐标原始单位。

## 3. 与历史方法对比：哪条路更适合

| 历史方法 | 结论 | 本次能否复用 |
|---|---|---|
| L1~L5 几何代价场 / 水平切 / `c̄<0.4` | `cut_cost AUC=0.5185`，几何场塌陷 | ❌ 不能靠自动几何量猜「哪条线该顺、哪个角该圆」 |
| L6~L8 真值集 / 语义预测 | 设计师真值集未产生；空间分区标签 acc 0.936 但只是复述位置；L7 误差放大、L8 同 acc 下边 F1 仅 11.58% | ❌ 语义监督缺位，自动分件不可信 |
| **L9 人工画线 + `refine_seam.py`** | 弧长重采样 → 切向 Taubin → 3 环邻域投影回表面 → 面带串联 → 闭环复验；统一口径转折角 6688°→2110°（−68.5%），闭环 2→2 | ✅ **直接迁移**：把「沿网格边的折线变平滑线段」的分工搬到分色边界/零件轮廓 |
| **绑骨拆分（本次 13-）** | 连通块分离 → 23 件封闭 STL → 刚性蒙皮 → Blender 骨架 | ✅ 分件结果不用重做；骨架与 MST 层级保留，但运动学语义仍待人工命名 |
| 全局 Laplacian / SDF 重网格 / Subdivision | 未测；有收缩、糊细节、破坏间隙、面数爆炸风险 | ⚠️ 只作**可选风格化**，且必须逐件 + 守恒检查，不作为默认 |

### 选定的路线（分工不变，把「人工意图 / agent 加工」从割线推广到外观）

```
人：决定哪些表面/边界要圆润、要什么分色线（设计意图，不自动猜）
        ↓
agent：① 完整几何 + 光滑法线 + 抗锯齿的显示链路（修 L0/L2）
       ② 沿边界做「重采样 → 切向平滑 → 投影回表面 → 复验」（复用 L9，修 L3）
       ③ 逐件可选几何圆润化，每轮量化反思（修 L4，但标为风格化）
       ④ 全部在 Blender 内落地为 .blend / GLB / 可见证据
```

不采用「全自动猜缝 + 全局平滑」——那正是 L1~L8 已经证伪、且会违反约束 1 的路线。

## 5. 已撤销 / 降级的说法（留痕）

- ❌「Shade Smooth 能解决棱角」→ 实测 flat/smooth 仅 1.76% 像素差，只改着色不改轮廓。
- ❌「所有模型几何上都是棱角」→ 5 个资产中位二面角 0.15~2.76°，≥30° 边仅 0.3~3.6%。
- ❌「flat 对照图有效」→ 首版在 `Weighted Normal` apply 之后才切 flat，自定义法线覆盖了
  `use_smooth`，两图几乎相同；R2 重做。
- ⚠️「圆润 = 更好打印」不自动成立；锐边不是打印硬伤，薄尖刺与间隙才是。

## 6. R5：把「绑骨拆分」与「L9 人工画线」结合，找更适合的路

### 6.1 先确认一个内在矛盾

用户想要「网上那种平滑连接、方便打印」，同时又要「拆分成 23 件」。
**这两件事直接冲突**：平滑连接意味着零件之间连续过渡、分件缝消失；
可拆分要求分件缝清晰且留装配间隙。当前模型正好是后者
（23 个互不连通的封闭件，间隙 0.00007~0.0022）。所以「颜色分割线」
必然存在，且按连通块硬赋值时只能沿三角网格边走 → 折线，不是平滑曲线。

放大实测（`分色边界-放大证据.png` / `boundary_metrics.json`）：
颜色边界像素 31,889（全图 2.635%）；可追踪的 137 条扫描行中
**43.80% 出现 |Δx|>1 的跳变**、p90 达 15.2 px。
（口径说明：多件轮廓混在同一扫描行，该指标只证明「边界不平滑」，
不用于精确归因到单条边。）

### 6.2 三条路线对比

| 路线 | 做法 | 分件线 | 可拆 23 件 | 代价 / 可行性 |
|---|---|---|---|---|
| **A 显示层修复（本轮已做）** | 闭合 LOD + 平滑顶点法线 + 抗锯齿；Blender .blend 开 Shade Smooth | 仍是硬折线 | ✅ 保留 | 只解决「颗粒感」，不解决「分件线尖锐」 |
| **B 整体圆润化** | 合并 23 件 → SDF / Voxel Remesh → 平滑 → 重新分件 | 平滑连接甚至消失 | ❌ 需重做分件 | 体素尺寸必须小于 0.00007 才不粘死；会糊掉装甲细节；等于重新建模 |
| **C 人工定线 + agent 平滑（推荐）** | L9 画线器让人画想要的分件线 → `refine_seam.py` 重采样/切向 Taubin/投影回表面/闭环复验 → `split_from_drawing.py` 按线切 → 复用本轮骨架做刚性蒙皮 | **平滑曲线** | ✅ 保留 | 需要人画一条线；这是设计意图，不能自动猜 |

### 6.3 为什么推荐 C（与 L1~L9 证据链对齐）

- L1~L5：`cut_cost AUC=0.5185`，几何代价场塌掉 → **不能让算法自动决定缝在哪**。
- L6~L8：设计师真值集未产生；规则/空间分区标签 acc 0.936 只是复述位置；
  同 acc 下边 F1 仅 11.58% → **语义预测不可当真值**。
- L9：`refine_seam.py` 已实测把折线统一口径转折角 **6688° → 2110°（−68.5%）**，
  Hausdorff 0.199 mm，闭环 2→2、断点 0；且 `split_from_drawing.py` 端到端
  切出 2 大块、raw/refined 只差 6 个面 → **「把尖锐折线变平滑线段」这条链路已跑通**。
- 绑骨拆分（本轮）：23 件封闭几何 + 23 骨刚性蒙皮 + Blender 原生工程已就位，
  切开后可直接重新绑定，不用从零造骨架。

**所以最适合的路线不是「再找一个自动平滑算法」，而是把分工固定下来：**
> 人决定线在哪（设计意图）→ agent 把线变平滑并复验 → agent 按线切分并绑骨。
> 自动算法只做执行与校验，不做审美判断。

### 6.4 具体落地（等用户选线后执行）

1. 打开 `12-交互式画线分割/seam_draw.html`，在 3D 模型上单击落锚点画分件线，
   每段可拖中点调弧度，导出 JSON。
2. `python refine_seam.py <画线JSON>` → 平滑 + 闭环复验（大块数≠2 即告警）。
3. `python split_from_drawing.py <refined.json> --cap fan` → 两件 STL/GLB + 水密报告。
4. 用本轮 `build_blend.py` 的骨架/材质/灯光流程，把新零件在 Blender 里
   Shade Smooth + Weighted Normal + 刚性绑定 → 原生 .blend。
5. 每步复验：连通块数、边界边、非流形、体积、装配间隙（间隙 0.0001 量级，
   任何平滑位移超阈值即告警）。

### 6.5 本轮没有擅自做的事（诚实边界）

- 没有把 23 件合并成「一个平滑整体」——那会摧毁可拆分性，与主线相反。
- 没有把分色硬改成渐变带——用户要的是「平滑的一条线段」，渐变带是另一种东西，
  擅自替换等于偷换需求。
- 没有把全局 Taubin / 大宽度 Bevel 当默认交付——R3/R4 实测都证明收益不抵代价。
- 没有再改源 STL 几何——所有圆润化实验产物都单独存放并标注为对照／可调 modifier。
