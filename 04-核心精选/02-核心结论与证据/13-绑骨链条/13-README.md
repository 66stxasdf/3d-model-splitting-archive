## 一句话结论

**这个模型不需要"切"——它本来就是 23 个互相不连通、各自封闭的零件，被打包进了一个 STL。**

## 「绑骨」是怎么绑的

STL 格式只有三角形坐标和法线，**不可能带骨骼权重**，所以骨架必须现造：

1. **拆分**：`face_adjacency → connected_components`，23 个块各自导出独立 STL。
   不删面、不改拓扑、不评判缝的位置。
2. **骨架层级**：对 23 件两两算最近表面距离（每块抽样 4,000 顶点 + cKDTree），
   在距离矩阵上取**最小生成树**；root = 树中度数最大的节点（并列取体积最大），
   实测落在 `J_13`（度数 11，体积 0.004425，位于躯干中心）。
3. **刚性蒙皮**：每个顶点 `JOINTS_0 = [所属件的骨编号, 0, 0, 0]`、
   `WEIGHTS_0 = [1, 0, 0, 0]`；`inverseBindMatrices` 取各关节全局平移的逆。
   这是硬表面 / 分件角色的标准绑法：拖动一根骨，对应零件整块跟着动，零件本身不形变。
4. **输出 glTF**：`parts_rigged.glb` 含 `skins / JOINTS_0 / WEIGHTS_0 / COLOR_0`，
   23 个 joint 节点按 MST 挂成父子层级，可直接进 Blender / Unity / three.js。

**这不是**：自动热扩散软蒙皮、语义骨骼命名（头/左手/躯干）、机械关节设计。
骨骼名 `J_00 … J_22` 是中性编号，语义名请在 `manifest.json` 的 `bones[].name` 里人工填写；
层级是几何推断，不保证符合设计意图的可动关系。

## R1~R6：光滑外壳与「棱角」根因（2026-11-07 夜追加）

用户反馈「所有模型都有尖锐棱角、颜色分割线是尖锐曲线而非平滑线段」。
**先量化再动手，结论与直觉相反**，详见 `L10-棱角根因推敲与路线.md`
与 `迭代优化日志-2026-11-07.md`（五轮实测 + 每轮反思）。

核心结论：

1. **源模型不是棱角模型**。二面角中位 2.32°、≥30° 尖锐边仅 1.91%；
   横向测 5 个资产（含 02 宇航员 / 03 Minecraft / 10 月两个整体 STL）
   中位 0.15~2.76°、≥30° 边 0.30~3.61%。
2. **颗粒感主要是我自己的显示链路造出来的**：旧查看器是抽面 LOD
   （91,610 / 1,745,172 = 5.25%，必然留孔洞），三视角图是点云 z-buffer。
3. **STL 只存面法线**（抽样 20 万面，存储法线与叉积面法线点积 100% = 1.000000）
   → 导入 Blender 默认 Flat；但 `Shade Smooth` 严格对照只差 **0.97% 像素**，
   只改着色不改轮廓，**不是这个问题药**。
4. **三条「自动变圆」的路全部实测不划算**：
   全局 Taubin（≥30° 边只降 0.49 个百分点后反转、体积反而膨胀、最大位移是
   最小装配间隙的 38×）、Blender Bevel（`clamp_overlap` 把宽度钳死，
   0.0012/0.004/0.010 三档结果逐位相同，+29.93% 面换 0.95% 观感）、
   SDF/重网格（体素必须小于 0.00007 才不把 23 件粘死，不可行）。
5. **「颜色分割线尖锐」是硬标签 + 离散三角化的必然结果**：
   分色按连通块对面硬赋值，交界线只能沿三角网格边走 → 折线；
   放大实测 43.80% 扫描行出现 |Δx|>1 跳变。
6. **内在矛盾**：「平滑连接」与「可拆成 23 件」冲突——连接越平滑，分件缝越不明显。
   不能替用户决定风格。
