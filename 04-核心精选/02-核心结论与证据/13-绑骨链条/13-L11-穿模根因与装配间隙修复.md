# L11 · 黄色/绿色零件穿模：根因、量化与装配间隙修复

日期：2026-11-08　｜　对象：`13-绑骨拆分-23件刚性蒙皮` 的 23 件刚性蒙皮模型
用户观察（两条，均被实测证实）：
1. 「两个绿色零件应该是结构对称的」；
2. 「黄色部分和绿色部分有一部分模型形状相同，会出现穿模」。

用 `gen_thumbs.py` 逐件渲染、`make_contact_sheet.py` 拼成 `23件编号对照表.png`，
再把用户三张截图与缩略图逐一比对：

| 截图里的东西 | 真实编号 | 颜色 / 位置 |
|---|---|---|
| 左侧亮绿色板状装甲 | `part_02` | rgb(104,209,96)，质心 x=−0.075、z=0.438 |
| 右侧青绿色圆角板 | `part_07` | rgb(96,209,149)，质心 x=+0.100、z=0.443 |
| 黄褐色带铆钉的躯干 | `part_13` | rgb(209,177,96)，质心 x=+0.004、z=0.485 |
| 第二处黄绿小块 | `part_05` / `part_10` | 见 `clash_quick.json` |

`part_02` 与 `part_07` 同高度、左右分布，正是用户说的「应该对称的两个绿色零件」。
第三张放大图里，黄褐色表面上大量亮绿色锯齿状斑块，是 `part_02` 与 `part_13`
两个表面**近共面/互相插入**造成的深度竞争（Z-fighting），不是 L10 里那种
「颜色硬标签沿三角边走」的问题。

## 三、根因

**源模型是渲染/游戏用模型，不是装配式模型。**
装甲板 `part_02` 的内侧形状与躯干 `part_13` 完全一致（共形），建模时把装甲板
**嵌入**主体内部一截以避免露缝——这在渲染里看不出问题，因为嵌入部分永远被遮住。
按连通块拆成 23 个**各自封闭的独立实体**、再各配一根骨做刚性蒙皮之后：

- **几何上**：两个实体占据同一空间，最大互穿 5% 身高 → 3D 打印后物理上装不上；
- **显示上**：共面处深度缓冲竞争 → 视口里黄褐/亮绿锯齿状斑块（用户第三张图）。

这不是颜色标签问题，也不是拆分算法拆错了：源 STL 里就存在。
另外 `part_02`/`part_07` 镜像残差 11%，**源模型左右本身不严格对称**，
所以「把一侧镜像过去」不能自动修好穿模。

## 四、修复（已实施）

`fix_clash.py`，Blender 4.4.3 `BOOLEAN / DIFFERENCE / EXACT`：

1. 复制主体件，沿顶点法线外扩 `CLEARANCE = 0.0006`（装配间隙中位数 0.000288 的约 2 倍）
   作为切割体；
2. 从外挂件里减去它：`part_02 -= inflate(part_13)`、`part_05 -= inflate(part_10)`；
3. 布尔新增顶点重新赋 100% 刚性权重，`PartRig` 层级与其余 21 件一律不动；
4. 原工程 `parts_showcase.blend` **不覆盖**，另存 `parts_fixed.blend`。

| 件 | 面数 | 体积 | 边界边 / 非流形边 | 嵌入点（ray-casting） |
|---|---|---|---|---|
| `part_02` 前 | 119,278 | 0.00030652 | 0 / 0 | 728/1500（48.5%） |
| `part_02` 后 | **77,589** | 0.00020755 | **0 / 0** | **0/1500（0%）** |
| `part_05` 前 | 104,900 | 0.00017859 | 0 / 0 | 652/1500（43.5%） |
| `part_05` 后 | **82,028** | 0.00010566 | **0 / 0** | **0/1500（0%）** |

独立小样本复核（种子不同）：250/500→0/500、263/500→0/500；修复后两件仍
`is_watertight = True`。剩余贴合面到主体表面约 0.00056~0.0006，正好是设定的间隙。

**渲染图修复前后逐像素一致**（`clash_before_*.png` vs `clash_after_*.png`，
最大通道差 ≤1）。这是预期结果而非渲染失败：切掉的全是本来就藏在主体内部、
从任何外部视角都看不见的几何，**外观零变化**。

## 五、代价与边界（如实留痕）

1. **单位未知**：0.0006 是文件原始坐标。若模型高 0.888 对应 888 mm，则约 0.6 mm，
   是合理的打印间隙；若单位不同必须按比例换算。STL 不含单位元数据，未擅自猜测。
2. **失去嵌入定位**：切掉了 32% / 41% 的体积，这些原本是「插进主体里」用来定位的。
   现在零件只是贴合，没有卡扣/榫卯；要真能装，需要另加装配结构或胶接面。
3. **左右对称残差 11% 未修**。要严格对称，得用 `part_07` 的镜像替换 `part_02`，
   但那会改变外观，属于风格决定，留给用户确认。
4. **骨架层未加约束**：刚性蒙皮下单独拖动某一根骨，仍可制造新的穿模。
   可选做法：给贴合对加父子关系 / `Copy Transforms` 约束让它们一起动。
5. **只修了互穿最严重的两对**。其余 54 对 AABB 重叠未逐对处理，
   完整排名在 `clash_quick.json`，可按同样方法批量扩展。
6. 全量 ray-casting 诊断 `diagnose_symmetry_clash.py` 因单次分配 2.65 GiB
   内存失败，**未产出** `clash_diagnosis.json`；本报告所有结论不依赖那份失败结果。

## 六、中途被证伪 / 换路的记录

- **`signed_distance` 符号陷阱**：修复后它报「100% 点 sd<0」，看似更糟；
  但 ray-casting `contains` 是 0/600。近共面处 `sd` 的最近面法线符号不可靠，
  **判定实体内外必须用奇偶射线**，不能只看 sd 正负。这是本轮最容易下错结论的地方。
- **FCL 未安装**，`trimesh.collision.CollisionManager` 不可用，改用 KD 树近似筛 + 射线精判。
- **首版四联渲染对照**（AgX 色彩、相机没对准两件交叠区）几乎看不出差别，
  不能当修复证据；改做 `穿模证据-实体内外散点.png`（红=嵌入，绿=在外）。
- **matplotlib 未安装**，证据图改用 PIL 绘制。
- 第一版 `contains` 一次传 3000 点触发 1.16 GiB 分配，改分批 40~50 点。
