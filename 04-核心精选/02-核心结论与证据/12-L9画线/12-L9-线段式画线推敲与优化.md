# L9 线段式画线 · 推敲与优化

> 触发：用户反馈「左键一直按住画出来的线段太粗糙」，要求改为**单击落点 → 橡皮筋直线 → 再单击成段**，
> 且**线段必须贴在模型表面**、**agent 后台加工让它更平滑**、**两点成段后能人工改弧度**。
> 本文先把取舍和矛盾固定下来，再给实现规格与可证伪指标。实测数字见第 7 节（实现后回填）。

---

## 1. 先诊断：v1 为什么粗糙（源码级，不猜）

截图中黄色乱线的成因不是「手抖」这一个原因，是三个机制叠加：

| # | v1 源码 | 后果 |
|---|---|---|
| 1 | `pointermove` 里 `if(now-lastPick<16) return; addHit(pick(e))` | 每 16 ms 把一次 raycast 命中点直接 `cur.pts.push(p)`。鼠标每帧位移与抖动**原样变成折点**，200 ms 一笔就是十几个折点。 |
| 2 | `addHit()` 用 `facePath(last, f, 40)` 补两次命中间的 faces | `facePath` 是**无权 BFS**，优化目标是「最少面数」而非「最短表面距离」。模型三角面大小不均时，最少面数的路会明显绕远、跨到相邻凸凹区，于是线在头发 / 脸 / 头盔之间来回跳。 |
| 3 | 补出来的中间点用 `CEN[g]`（面心） | 面心折线本身带三角面尺度的锯齿；与真实命中点混在一条 `pts` 里，尺度不一致。 |

还有两个交互层的硬伤：

- **不可改**：`pointerup` 立刻 `strokes.push(cur)` 提交，画错只能整段撤销；
- **不可复现**：一笔的形状取决于当时帧率、鼠标速度和视角，同一个人画两次结果不同。

所以「改成线段式」不只是换输入方式，它同时要修掉无权 BFS 这个**算法层**的错误。只换交互、不换补路径算法，线仍然会跳，只是跳得少一点。

## 2. 需求形式化

| 用户原话 | 形式化定义 |
|---|---|
| 单击后生成一个点 | `anchor = {p ∈ 网格表面, f = 命中面, n = 该面法线}` |
| 移动鼠标连着点生成直线 | 从最后 anchor 到当前 hover 点的**空间弦**做橡皮筋预览 |
| 再到另外一点点击生成线段 | 提交 `segment(i→i+1)`，两点定一段 |
| 线段生成要在模型表面 | 提交的段是**表面测地折线**（面上路径），不是空间弦 |
| agent 后台加工线段使它更平滑 | 离线脚本消除面心折线的三角尺度锯齿，输出可复查的中间产物 |
| 两点确定一条线段后可以人工修改弧度 | 每段一个 `bulge ∈ [-1, 1]`，可拖动中点 / 数值输入，改完重算该段 |
| 思考推敲优化 | 显式裁决下列矛盾，给出可证伪指标，不把「看起来顺眼」当结论 |

## 3. 三处内在矛盾与裁决

### 矛盾 A：「直线」与「贴在表面」不能同时为真

曲面上两点之间的 3D 直线（弦），除退化情形外**不在曲面上**：凸区域弦埋进实体内部，凹区域弦悬在空中。
如果 UI 只画一条线，用户会以为切的是那条直线，后台实际切的是另一条测地线 —— 这是「显示的证据」和「执行的数据」不一致，与前面 L1~L8 反复纠的「机制对、证据错」是同一类错误。

**裁决：预览与真值分离，两条线同屏。**

- 细虚线（浅灰）= 两点空间弦，仅是「我指的是这两个点」的示意；
- 实线（黄）= 真正贴表面的测地折线，**后台 `loop_faces` 只从它生成**；
- 侧栏显示 `弦长 / 测地长 / 最大偏离` 三个数，让「弦 ≠ 表面路径」可量化。

代价：预览阶段要跑一次加权 Dijkstra（会节流 + 早停），不能像 v1 那样零成本画线。

### 矛盾 B：测地最短路未必是用户想要的缝

纯最短测地路径会抄近路穿过凹陷、贴着凸脊走，甚至绕到模型背面。
v1 的「补全：最短」模式在 README 里已经实测过：闭环同样成立，但小件只有 0.726 cm³（真值 22.68 cm³），偏差 85%。**闭环成立证明不了位置对**。

**裁决：以空间弦为软引导，不假装自动找对缝。**

路径权重
```
w(g) = 面心距 × (1 + λ · d(CEN[g], guide) / L)
```
`guide` 是用户两点连成的弦（有弧度时是 `A→H→B` 折线），`d` 为点到线段距离，`L` 为弦长，`λ` 默认 1.2、界面可调到 0（退化为纯最短路）。
这使路径既贴表面、又不会大幅偏离用户所指的方向。**λ 是显式暴露的旋钮，不是藏起来的超参**。

同时提供 `bulge` 让用户把「直线段」弯成弧：这是把设计意图交还给人，而不是让算法猜。

### 矛盾 C：平滑会改变割线，闭环可能不再成立

平滑（重采样 + 切向平滑 + 投影回表面）会改变面带位置，可能让闭环自交、断开、或把面带挪到薄壁处。
若平滑后直接拿去切、并默认「还是两块」，就是把「没验」当「验过」。

**裁决：平滑后必须重跑闭环判据。**

`refine_seam.py` 用与 `split_from_drawing.py` 同口径的 `bfs_groups` 重算大块数，
并报告平滑前后：面带数、大块数、两大块面数、Hausdorff 单向偏差。大块数 ≠ 2 时**如实报错**并保留原 JSON 不覆盖。

## 4. 算法规格

### 4.1 表面段生成（前端，提交时）

`geoPath(fa, fb, guide, λ)`：面对偶图上的 Dijkstra，权值如上式，早停于 `fb`，最大展开 8000 面（防跨背面 / 防卡死）。
面对偶图而非顶点图，理由是**后台切分的数据契约本来就是面带 `loop_faces`**，面序列即真值，不需要更精细的顶点级测地。
首尾点用真实 anchor 命中点，中间点用面心 —— 保证端点精确落在用户点击处。

### 4.2 弧度（前端，可反复调）

设段两端 `A, B`，弦 `d = B - A`，`L = |d|`，中点 `M`，两端法线均值 `n`，
切平面内侧向 `s = normalize(n × d)`（退化时换轴）。

```
H0 = M + s · (bulge · L · k),   k = 0.60
H  = projectToSurface(H0)        // 沿 ±n 双向射线求交，取最近；失败则回退 M 并标记
segment = geoPath(fa→hf, guide A→H)  ++  geoPath(hf→fb, guide H→B)
```

- `bulge = 0` 退化为单段直线（仍贴表面）；
- `H` 始终投影回表面，弧**不会悬空**；
- `k` 从 0.30 提到 **0.60 是实测逼出来的**：k=0.30 时 `bulge=0.6` 只偏移 ≈0.9 mm（本模型一个三角面尺度），
  中点投影后仍落回原面，段面数 19→19、`faces_changed=False`，等于弧度调节没生效；
  k=0.60 后同样 `bulge=0.6` 得到 19→25 面、中点 z 从 71.0 投到 75.3、`faces_changed=True`。
- 拖动中点 handle 时，用「过 H 的切平面 ∩ 鼠标射线」反算 bulge，比按屏幕像素位移更准；
- 侧栏同步给 `[-1, 1]` 数值滑块，保证可复现。
- **已知边界**：中点沿 ±n 投影可能落到邻近另一片表面（实测 z 抬升 4.3 mm）。
  工具把 `handle` 实际坐标与 `projection_ok` 一起导出，不隐藏这一偏移。

### 4.3 后台平滑（`refine_seam.py`）

1. **弧长重采样**：把段折线按 `ds = 0.6 mm` 均匀重采样（模型高 100 mm）；
2. **切平面内 Taubin 平滑**：`δ = (p₋₁+p₊₁)/2 − p`，去掉法向分量 `δₜ = δ − (δ·n)n`，
   依次 `p += λδₜ (λ=0.5)`、`p += μδₜ (μ=−0.53)`。Taubin 而非普通 Laplacian，避免折线整体收缩；
   **只平滑切向分量**，法向不动，防止离开表面。默认 **8 次迭代**（见 7.3 的拐点扫描）；
3. **投影回表面，但限制在「原割线面带的 3 环邻域」**：用 `F[cand]` 造子网格再
   `trimesh.proximity.closest_point`，把 `triangle_id` 映回原面号。
   全局最近点在薄壁处会穿到模型背面 —— 那既是平滑改变设计意图，也会让面带断裂（见 7.4）；
4. **重映射并全局串联面序列**：`triangle_id` 去重 → 面邻接 CSR 上 BFS 补断点 →
   用户段与 `completion_faces` **一起**再串一次，保证平滑换掉首尾面后闭环不漏；
5. **闭环复验**：用 `split_from_drawing.py` 同口径 `connected_components` 重算大块数；
6. **输出** `*_refined.json`（仍是 `loop_faces` 契约）+ 对照报告 + 对照 PNG。原 JSON 不覆盖。

**公平比较**：平滑前后**都**重采样到同一 `ds` 再算转折角，否则点数不同会造成「假改善」。
另跑 `--iters 0`（只重采样+投影、不平滑）作对照，把改善正确归因。

**平滑的对象要说清**：被消掉的是**面心折线的三角尺度锯齿**，不是把用户画的直线掰弯。
用户的两点与 `bulge` 是意图，平滑只在不越过 `max_dev_mm` 的前提下修掉离散化毛刺。

### 4.4 数据契约 v2（向后兼容）

```jsonc
{
  "schema": "seam_draw/v2",
  "mode": "polyline_segment",
  "anchors":   [{"point":[x,y,z], "face":f, "normal":[x,y,z]}],
  "segments":  [{"a":0,"b":1,"bulge":0.0,"guide_lambda":1.2,
                 "faces":[...], "pts":[...], "handle":[...],
                 "chord_len":0, "geo_len":0, "max_dev_mm":0}],
  "closed": false,
  "user_faces": [...], "completion_faces": [...],
  "loop_faces": [...], "cut_edges": [...],   // ← v1 契约字段全部保留
  "band_width": 1, "close_mode": 2, "stats": {...}
}
```

`split_from_drawing.py` 只读 `loop_faces / band_width / nf`，因此 **v2 JSON 可以直接喂给原后台脚本**，
不需要改切分逻辑；仅把 schema 白名单加上 v2。`demo_seam.json` 等 v1 样例继续可用。

## 5. 可证伪指标（不靠「看起来顺眼」）

| 指标 | 定义 | 期望方向 | 若不满足说明什么 |
|---|---|---|---|
| 折点数 / 段 | 用户锚点数 ≡ 段数+1 | 与帧率、鼠标速度无关 | 若随帧率变 = 又退回连续采样 |
| 转折角总和 | Σ angle(pᵢ₋₁→pᵢ→pᵢ₊₁)，度 | 线段式 ≪ 拖拽式；平滑后进一步下降 | 平滑没起作用 |
| 弦长 / 测地长 | 两点直线 vs 表面路径 | 比值 < 1，偏离越大比值越小 | 比值≈1 说明该段近似平面，正常 |
| 离面距离 | 路径点到网格表面距离，mm | 投影后 ≈ 0 | > 0 说明线悬空，违反「在表面」 |
| 最大偏离弦 | 测地路径点到空间弦最大距离，mm | 有界、可调 λ | 无界 = 绕到背面去了 |
| 平滑前后 Hausdorff | 单向最大位置偏差，mm | 小于阈值（默认 1.5 mm） | 超阈值 = 平滑改变了设计意图 |
| 闭环判据 | 删带后 >1% 面的大块数 | 前后都 = 2 | ≠2 = 平滑把环弄断了，必须回滚 |

## 6. 明确不做（边界）

- 不自动找接缝、不预测语义部件、不加载 `cut_cost`、不用 L1~L8 的任何代价场；
- 不把「闭环成立」当「缝位置正确」；
- 不因为平滑后曲线好看就跳过闭环复验；
- 不覆盖用户导出的原 JSON，`refined` 另存；
- 「人工画出来」仍是用户动作：agent 只做补全、平滑、执行切割，不替用户产生设计意图。

## 7. 实测

> 全部来自无头 Edge 真实前端 + 后台脚本，数字可复算：
> `selftest_v2.json` / `line_quality_metrics.json` / `refine_report.json` /
> `refine_report_control_iters0.json` / `refine_iters_sweep.json`。
> **样例用的是 demo 水平切片轮廓降采样成 12 个锚点，不是用户真实手绘**；
> 用它验证的是「新链路能不能跑、线条离散化改善多少」，不是「这条缝好不好」。

### 7.1 交互链路与 v1 兼容性

- 无头浏览器里派发**真实 `PointerEvent`**：两次左键单击 → `2 锚点 / 1 段 / 38 面`，
  弦长 `8.862 mm`、测地长 `11.746 mm`（比值 0.754，路径确实贴表面绕行而非走空间直线）。
- 三种补全的实测数字与 v1 **逐一吻合**，证明改动没有静默改变已验证的结论：

  | 模式 | 补全面 | 闭环面带 | 两大块 |
  |---|---:|---:|---|
  | 最短 | 90 | 309 | 87,762 / 2,222 |
  | 绕背 | 87 | 306 | 88,110 / 1,874 |
  | 沿画线平面 | 275 | 494 | 74,862 / 15,124 |

- **弧度**：`bulge=0.6` → 第一段 19→25 面、20→27 点、`faces_changed=True`，中点 z 71.0→75.3，`projection_ok=true`。
- **λ 扫描**（12 锚点 / 11 段）：λ=0 / 1.2 / 3.0 → 最大偏离弦 `2.499 / 1.790 / 1.586 mm`，
  转折角 `9746 / 10716 / 11016°`。
  **真实 trade-off**：引导越强越贴用户所指方向、越不绕背，但面心/边中点折线反而更碎。
  λ 是显式旋钮，不藏这个代价。

### 7.2 线条质量：统一口径三联对照

三条线来自**同一份**前端产物，全部重采样到 `ds=0.6 mm` 后再算转折角：

| # | 折线 | 原始点 | 重采样点 | 转折角 | 弧长 mm | 相对 ① |
|---|---|---:|---:|---:|---:|---:|
| ① | 面心（v1 口径，由同一份 faces 反算） | 206 | 154 | 6687.93° | 76.933 | — |
| ② | 边中点（v2 线段式） | 207 | 138 | 4837.02° | 72.665 | **−27.7%** |
| ③ | Taubin 平滑后（iters=8） | 138 | 112 | 2110.09° | 65.035 | **−68.5%** |

见 `line_quality_comparison.png`。边中点比面心更贴表面：前端自检里同一面带的转折角
`14675.77° → 10715.82°`、路径长 `94.51 → 82.45 mm`（另一口径，与上表不可直接相减）。

**改善来源必须拆开算**：`--iters 0`（只重采样+投影、不平滑）已把 `4837° → 3400°`（−29.7%），
Taubin 平滑再降到 `2110°`（总 −56.4%）。所以**平滑本身贡献 26.7 个百分点**，
不能把 56.4% 全算给平滑。

### 7.3 迭代数扫描与拐点

| iters | 转折角 | 降幅 | 弧长 mm | Hausdorff max | 中位 | 最大离面 | 大块 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 | 3400° | 29.7% | 68.88 | 0.040 | 0.021 | 0.0000 | 2 |
| 3 | 2429° | 49.8% | 65.85 | 0.136 | 0.046 | 0.0248 | 2 |
| **8** | **2110°** | **56.4%** | **65.03** | **0.199** | 0.053 | 0.0395 | **2** |
| 15 | 2054° | 57.5% | 64.56 | 0.247 | 0.064 | 0.0589 | 2 |
| 25 | 1927° | 60.1% | 64.43 | 0.271 | 0.077 | 0.0738 | 2 |
| 40 | 1839° | 62.0% | 64.05 | 0.290 | 0.086 | 0.0888 | 2 |

3→8 再降 319°，8→15 只降 56° 而 Hausdorff 继续涨 → **默认取 8**。
全部迭代下 Hausdorff max 都 ≪ 1.5 mm 阈值、`max_off_surface` ≤ 0.089 mm，闭环始终 2 大块。

### 7.4 闭环复验：矛盾 C 真的发生了，也真的修好了

| 阶段 | 结果 |
|---|---|
| 首版：全局 `closest_point` 投影 | 大块 **2→1**、55 处面断点 → 脚本按设计**告警**，不假装成功 |
| 加「3 环邻域」约束后 | 断点反而 **113** 处 → 说明根因不在投影范围 |
| 查到面邻接 CSR 构建 bug | `nbr[cur[a0]]=a1` 的向量化赋值对重复面号只留最后一次，留下未初始化空洞 |
| 改 `np.argsort(..., kind="stable")` 构造 CSR | 单测抽样 2000 条对偶边 **2000/2000** 通过；断点 **0**、大块 **2→2** |

这正是第 3 节矛盾 C 的实证：**平滑会在拓扑上把闭环弄断**，必须复验、必须能回滚。
修复后默认运行：面带 407→404，补断点 0，Hausdorff max 0.199 mm，无告警。

### 7.5 端到端切分（`split_from_drawing.py` 直接吃 v2 / v2+refined）

| 输入 | A 面 | B 面 | 均衡度 | B 体积 | 大块 |
|---|---:|---:|---:|---:|---:|
| 原始 v2 JSON | 73,899 | 16,086 | 0.2177 | 23.874 cm³ | 2 |
| refined（iters=8） | 73,896 | 16,088 | 0.218 | 23.835 cm³ | 2 |

两者只差 3~4 个面 —— 平滑让线更顺，但**没有偷偷改变切分结果**。
如实保留的硬伤：`part_A` 仍有 **1 条非流形边、不水密**，`part_B` 水密；
这是原有「带面按邻居多数回分配」链路的已知问题，本次未修，不掩饰。

### 7.6 限定

- 样例锚点来自 demo 轮廓降采样，**用户真实手绘的割线尚未产生**；
  「人工画出来」仍是用户动作，agent 不替用户产生设计意图。
- 闭环成立 ≠ 缝位置正确（README 里 85% 偏差的最短模式同样分出 2 块）。
- 平滑只改形状，不改 `anchors` / `bulge`；agent 补全段不平滑（它是几何外推）。
- 三个硬阻塞不变：人工设计师接缝真值集、语义部件预测监督、下游可装配指标。
- 本轮**未做任何资产库写操作**；如需同步，另列清单等你确认。
