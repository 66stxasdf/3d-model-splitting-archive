## 1. 为什么这么做（承接 L18）

L18 实测结论：新 STL 是 **500,000 面 / 1 个连通块 / 水密 / 零边界边**，

本轮选 A + B：**先看清，再把「人工画线 → 后台真切割」这条主线真正打通**，
而不是再写一份分析报告。刻意**不做水平切割**（用户明确否定过）。

## 4. B1：画线器换几何（两个真实踩坑）

### 坑 1：STL 是 triangle soup
首次 LOD 降面崩成 34,206 个碎块、体积只剩 11%。根因不是模型也不是算法：
`process=False` 读进来是 **1,500,000 个互不共享的顶点、500,000 个独立碎片、
1,500,000 条边界边**，降面算法看不到面邻接，只能每个三角形各自塌缩。
改 `process=True` 先焊接 → 249,936 顶点 / 750,000 边 / 1 连通块 / 水密，
再降面即正常。诊断数据留在 `l19_lod_probe.json`（含 4 档 sweep）。

### LOD 代理选择
取 **89,954 面 / 44,933 顶点**（≈ L9 原版 90k 面，**交互性能是已实测过的基线**）：
体积比 0.999121（误差 0.088%）、面积比 1.000154（误差 0.015%）、单一主连通块；
剔除 24 个 2~4 面孤立小碎片（46 面）；剩 10 条非流形边不影响画线器
（画线只需要三角形 + 面邻接图，不要求严格水密）。
高模面心 → 最近代理面心：**99.517% < 1 mm**，中位 0.145 mm，p95 0.436 mm。

### 生成方式
用 `l19_patch_seam.py` 读 `gen_seam_draw.py`（52 KB 已验证模板）做**最小字符串补丁**
生成 `gen_seam_draw_new.py` 再执行，而不是重写模板——避免引入交互回归。
7 项补丁逐项断言：输出目录、数据源、`Z0` 移到中段 50.6、HUD 改实测量、
3 处 mesh 溯源、输出名（`seam_draw_new.html` / `demo_seam_new.json` / `_check_new.mjs`）。
`LAB` 全 0、语义色改中性灰、HUD 写明「未分件」，**不伪装成已分件**。

### 自检（不是「文件生成了」就算）
`l19_html_verify.py` 把 HTML 内联几何逐字节解码，**13/13 全过**：
POS 809,586 个 int16、ADJ 269,822 个 uint32（索引最大 89,953）、
NRMQ 809,586 个 int8（平均模长 126.25）、EMID 404,733、LAB 89,954 全 0；
**POS 坐标还原误差 0.0099996 mm**（正好是 int16/Q=100 量化的理论上界 0.01 mm）。

`l19_browser_check.py` 用 Edge 无头加载 `?selftest=1`，**真的跑通整条 JS 链路**：
`nf=89954 / ne=134911 / splitOK=true`；真实两次 PointerEvent 单击 →
2 锚点 / 1 段 / 31 面、弦长 8.884 mm、测地 12.096 mm；
bulge 0.6 → 面 12→15、点 13→17、`faces_changed=true`、`projection_ok=true`；
3 种补全模式、3 档 guide_lambda、2 种点模式全部产出。
前端还自己导出了 `frontend_seam_v2.json`（205 面）——这份**未闭合**，后面被流水线拒收。

## 5. B2：真切割（非水平）

### 割线
`l19_make_slanted_seam.py` 在 LOD 网格上用**倾斜 9.65°** 的平面求交：
423 个跨切面、最长闭环 **399 面**、`closed=true`；
闭环点 PCA 最小二乘重拟合平面 **RMS 0.00203 mm**、最大偏差 0.00503 mm。
后台只读重拟合值，不人工搬运预设常数。位置在颈部高度，
切出来正好是「头 / 身体+底座」——手办分件打印的典型接缝。

### 切割
`l19_cut.py` 用半空间盒（800³，局部 −Z 面落在拟合平面上）做
`BOOLEAN / INTERSECT / EXACT` 与 `DIFFERENCE / EXACT`：
10.4 s / 10.5 s → A 192,852、B 308,191 个多边形。

**坑 2 与坑 3**：
- 布尔切面是 **ngon**（A 525、B 518 个非三角多边形），只导出三角形会丢面漏水
  → 加 `bmesh.ops.triangulate` 全三角化，得 A 194,408 / B 309,740 面。
- 二进制 STL header 必须**严格 80 字节**，首版写成 71 字节导致面数字段错位、
  trimesh 读成 `Scene` → 修正并加断言，复验 `file_size == 84 + 50*faces` 通过。

### 薄碎片的诊断与剔除（不糊弄判据）
首轮复验 10/11，唯一失败项：B 有 **2 个连通块**。
`l19_diagnose_components.py` 查明第二块是 210 面 / 107 顶点 /
**0.349 mm³（占 B 体积 0.0012%）**、厚 0.41 mm、质心距切面 −0.0425 mm 的贴面薄片——
斜平面擦过表面凸起时的布尔残片，不是零件。

没有把判据改成 `>=1` 蒙混过关，而是在流水线里加显式一环 `l19_cleanup.py`，
**四条同时满足才剔除**：面数 < 主块 0.5%、体积 < 总体积 0.01%、
质心距切面 < 1 mm、沿法向厚度 < 1.5 mm。幂等，重复执行 `removed=0`。

### 独立复验（11/11）
`l19_verify_cut.py` 用 trimesh 从**导出后的 STL 重新读回**：
A、B 均水密 / 边界边 0 / 非流形边 0 / 绕序一致 / 各 1 连通块；
体积和 56,093.787 mm³，**相对误差 6.23e-6**（这 6.23e-6 是物理剔除 0.349 mm³
碎片的真实结果，不是数值漂移）；bbox 并集还原偏差 7.17e-6 mm；
互穿率 0.35% / 0.15%（切面共面处的射线数值误差）；两切面有符号距离 ≈0；
倾斜 9.65° 确认非水平。

## 7. 一键流水线与主动拒收

`l19_pipeline.py`：`--seam <画线器导出 JSON>` → 校验 → 从割线点 **重算** PCA 平面
（不信任文件自带的 `plane_fit`）→ 写 `l19_pipeline_plane.json` →
Blender 布尔 → 清碎片 → 独立复验 → 汇总。

准入条件：**已闭合 + ≥12 个闭环点 + 共面 RMS < 0.5 mm + 面索引合法**。
不合格就 `REJECTED`，**不执行任何切割，已有产物保持不变**。

两次实跑：
- `demo_seam_slanted.json` → `SUCCESS`（布尔 24.62 s / 清理 8.33 s / 复验 59.37 s，11/11）。
- `frontend_seam_v2.json` → `REJECTED`，理由「割线未闭合（closed=false），
  后台无法定义切割体内外」；133 个点从 `segments[].pts` 正确读出，重拟合 RMS 0.4432 mm。

`l19_cut_showcase.blend` 把两件做成独立可选中对象（`L19_头部_上半` /
`L19_身体底座_下半`），分色、打开即所见，另存贴合 / 爆炸两张渲染。

## 7.5 曲面分支：非共面割线也能切（收尾追加）

平面分支只吃「共面闭环」。为补上这个缺口，又做了一条**由割线点驱动**的曲面分支：

- **输入**：`demo_seam_curved.json`，抛物面 `z = 64 + 7·(x/31)²` 与 LOD 网格真实求交，
  402 个跨切面 / 387 面闭环 / **共面 RMS 0.6701 mm**（远超平面分支 0.5 mm 阈值，
  所以平面流水线确实会拒收它）。
- **v1 失败留痕**：用径向环法构造膜，因闭环**非星形**（8 次极角回折）折叠自交，
  cutter 出现 5 条非流形边 / 5 个连通块 → 判定不可用，没有拿去布尔。
  `l19_curved_seam.py` + `l19_curved_seam_report.json` 完整保留失败证据。
- **v2 成功**：改 **2D Delaunay 三角化**（不假设星形）——闭环点投影 XY 作内点、
  300 mm 大圆 52 点作外框、环外高度回落到拟合平面、
  822 个三角形组成高度场膜；凸包侧壁 + 顶盖挤出成封闭实体。
  cutter **491 顶点 / 978 面 / 水密 / 绕序一致 / 零非流形 / 1 连通块**。
- **端到端接口**：`l19_cutter_from_seam.py` 完全从**画线器导出的 `loop_points`** 构造 cutter，
  不含任何预设曲面方程；与 v2 预设版产物拓扑逐项一致（491/978/体积 83,492,562.3），
  证明是同一条割线在驱动，不是硬编码曲面。
- **实跑**：`l19_pipeline_curved.py` → cutter 3.64 s / Blender 曲面布尔 5.92 s
  （INTERSECT 1.6 s + DIFFERENCE 1.8 s）/ 独立复验 44.22 s → **SUCCESS，10/10**。
  A 192,048 面、B 315,980 面，均水密、各 1 连通块；
  **体积守恒误差 2.97e-10**、bbox 7.17e-6 mm、互穿 0.9%/0.13%。
- **切面确实弯曲**（关键证据）：落在曲面上的切面顶点，其 z 随 x 呈二次变化——
  x=−19.4→65.99、−11.6→65.20、−3.9→64.14、+3.9→64.14、+11.6→65.30、
  +19.4→66.52；z 跨度 **3.06 mm**（平面切割为 0），
  顶点到抛物面中位偏差 0.0018 mm。爆炸渲染里 B 件顶部切面呈明显波浪状。

两条分支的分工：`closed=false` → 拒收；`closed=true` 且共面 RMS<0.5 mm →
`l19_pipeline.py`（平面布尔）；`closed=true` 且不共面 → `l19_pipeline_curved.py`（曲面布尔）。
**曲面 cutter 目前按「高度场」建模**，即割线需在 XY 投影上可参数化为单值曲面；
自相交或垂直回折的环仍需另做处理。

### 统一入口（收尾补齐）

`l19_pipeline_auto.py` 读一份割线 JSON，按闭环点 PCA 的共面 RMS 自动路由并**真正执行**：
`closed=false` → `REJECTED`；`RMS<0.5 mm` → `l19_pipeline.py`；
`RMS≥0.5 mm` → `l19_pipeline_curved.py`。三路实跑：

| 输入割线 | 共面 RMS | 路由 | 结果 |
|---|---:|---|---|
| `demo_seam_slanted.json` | 0.0020 mm | 平面布尔 | SUCCESS（88.77 s） |
| `demo_seam_curved.json` | 0.6701 mm | 曲面布尔 | SUCCESS（54.03 s） |
| `frontend_seam_v2.json` | — | 拒收 | REJECTED（未闭合） |

另出 `L19-平面与曲面切割对照.png`：四联渲染 + 切面剖面曲线 + 数字表。
剖面里两条曲线**都用实测切面顶点按 x 分箱的 z 均值**（口径一致，不用解析公式），
蓝线单调直线、橙线 U 形二次曲线，直观区分两种切面。
