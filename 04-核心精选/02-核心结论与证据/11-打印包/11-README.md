## 二、「这是什么意思」——两套颜色别搞混

- **屏幕类别色**：截图里的彩虹色，是 L8 查看器按 golden-angle HSV 生成的 14 色，作用只有一个——**把 14 类区分开**。它不代表真实颜色。
- **建议耗材色**：`manifest.json` 里按角色语义给的 `rgb`（白头盔、金头发、肤色脸……）。**分色 3MF 用的是这套**，一页纸表格里每行也并列了两个色块。
- **青色锯齿线**：相邻三角面「语义标签不同」的共享边，共 **2,119 条 / 1.57%**（`costfield_validity.json`）。它沿网格边走，所以是锯齿，不是平滑曲线；它是**标签推导出来的边界**，不是设计师手绘的藏缝，也不是切割路径。

标签本身由 `07-脚本工具/tools/struct_split.py` 的高度带 / 前后 / 凸出深度规则生成，`L8` 已证明这套标签有 93.6% 能被纯空间分区复述，**不能当作人工设计真值**。

## 三、「怎么分别」

`parts_id_sheet.png` 正面视图上有 00~13 编号标签（做了碰撞避让 + 引线），表格按编号给出：中文名 / 英文 id / 文件名 / 三角面 / 尺寸 / 体积 / 材料上界 / 建议耗材色 / 摆放 / 邻接件数。
`print_manual.html` 点左侧任一件可单独查看并自动聚焦；「分件陈列」把 14 件按 4×4 网格各占一格铺开（头部几件质心重合，径向爆炸会把它们继续叠在一起，所以改用网格）。

## 四、「怎么打印」

1. **备料与排产**：`print_worksheet.csv`（UTF-8 BOM，Excel 直接开）/ `print_worksheet.md`。14 行含朝向、支撑、耗材色、风险分级；`print_data.json` 是同数据机器可读版。
2. **切片**：把 `astronaut_kid_14parts.3mf` 拖进切片软件。它是 14 个独立 object + 14 色 `basematerials`，每个三角形带 `pid/p1`，便于按对象分配耗材。
3. **纸面作业单**：`print_manual_printout.pdf`（浏览器打印输出的 2 页成品：第 1 页 A4 识别图，第 2 页作业单 + 打印前必读），或直接在手册里 Ctrl+P。
4. **原始几何**：14 个 STL 仍在 `04-分件结构分析/parts_struct/part_*.stl`，本包没有改动它们。

### 打印前必读（硬伤）

`assembly_check.json` 实测：**19 对贴合分界面，中位间隙 0.1187 mm；11 对互相内侵，最大 0.2935 mm**。
这些件是从同一张连续表面按标签切开、各自**原地加厚 1.2 mm** 得到的，配合面近乎零公差甚至互相穿插 —— **1:1 打印出来会顶死，不是可直接插装的套件**。
要能装，必须在分件阶段给配合面做**单侧 0.15~0.25 mm 偏置**（缩一件或放另一件），并补定位榫与装配顺序。本包只报告，不做修正。

其余可切片性：14 件全部水密、无非流形边。但壁厚仅 1.2 mm（0.4 mm 喷嘴建议 ≥3 条外壁）；眼睛 / 背包容积 < 0.1 cm³，注意最小特征与支撑拆除。按朝下面积占比 ≥10% 判「可平放」，14 件里**仅 2 件**（左右靴）达标，其余建议底筏 / 支撑。

### 自查中修掉的问题（留痕）

- `probe_assembly_fit.py` 用 manifest 的 `name` 作键，与带编号的文件键不匹配 → **14 件中文名与配色全部落空**，已改为按 `file` 字段建键并重跑。
- 识别图最初用 STL 薄壳做画家算法渲染 → 相邻件壳面互相穿插，出现彩色马赛克；改用**单层原始标签网格 + 逐像素 z-buffer**，并去掉背面剔除（原网格绕序不一致，按法向剔除会漏外表面、侧面出现异色条纹）。
- 编号 00/01、12/07 质心重合 → 标签碰撞避让 + 引线。
- 手册把 `apply()` 提前调用，`focus()` 命中 `tgt` 的暂时性死区 → **整页全白**，已修并加运行时错误捕获。
- three.js 源码自带 `window.__THREE__`，与我的内联占位符撞名 → 占位符改名。
- 默认用浅色耗材色 + 强光照 → 模型过曝发白；改默认类别色、降光照、列表改为 flex 撑满（原来裁掉 13 背包）。
- 径向「爆炸」把头部几件继续叠在一起 → 改 4×4 网格陈列；视点 z 从 75 修正为 50，最后一行不再被裁。

## 七、明确没做的

- **未在真实切片软件（BambuStudio / OrcaSlicer / PrusaSlicer）中实测导入 3MF**：只做了 ZIP/XML 结构校验与 trimesh 几何读回，颜色是否被切片软件识别为 14 种耗材需你导入后确认。
- 未做自动摆放优化、未生成带公差的修正 STL、未做定位榫设计、未估算真实耗材用量（表里是按 100% 实心 PLA 密度 1.24 g/cm³ 算的**材料上界**，不是实际用量）。
- 「建议耗材色」是按角色语义做的人工映射，不是实测颜色；「风险」分级只依据体积与最小边长，未做切片仿真。
- 接缝仍是规则化语义分件，**不是人工设计师手绘的藏缝**；这套标签不能替代真值集。
